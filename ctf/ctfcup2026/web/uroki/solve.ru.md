# Uroki: записать, прочитать, а потом попросить планировщик

[English](solve.md)

## 0. Приложение

Школьный журнал: создать урок, приложить файл, открыть карточку урока, скачать вложение. В архиве Flask-приложение, база SQLite в `/data`, каталог загрузок `/data/uploads` и конфиг supervisor, который поднимает gunicorn и воркер Celery с beat.

Флаг лежит в `/flag.txt`, и `entrypoint.sh` заканчивается двумя строками, которые всё решают:

```sh
chown app:app /flag.txt
chmod 0000 /flag.txt
```

То есть файл существует, принадлежит пользователю, от которого работает приложение, и не читается никем, пока не изменится режим. Эта деталь и определяет форму эксплойта.

Зачем этот шаг: чтение entrypoint сразу говорит, что «прочитать флаг» это не один шаг, а два, и второй требует исполнения кода от пользователя `app`.

## 1. Абсолютное имя ломает каталог загрузок

`storage.clean_name` убирает разделители пути только при наличии `..`, обратного слеша или управляющего символа:

```python
UNSAFE = re.compile(r"\.\.|\\|[\x00-\x1f]")
def clean_name(name):
    name = (name or "").strip()
    if UNSAFE.search(name):
        name = os.path.basename(name.replace("\\", "/"))
    return name.strip() or FALLBACK_NAME

def save_attachment(folder, file):
    path = os.path.join(folder, clean_name(file.filename))
    file.save(path)
```

Имя вида `/data/uroki.db` не содержит запрещённых шаблонов, а `os.path.join` отбрасывает первый аргумент, если второй абсолютный. Значит загрузка пишет куда угодно, куда может писать процесс.

Дальше обработчик сохраняет полученный путь в базу и вызывает `db.set_attachment(id, f.filename, path)`.

Зачем этот шаг: это первый примитив, произвольная запись файла, и его уже достаточно, чтобы подменить базу самого приложения.

## 2. Чтение произвольных файлов

Обработчик скачивания берёт путь из базы и передаёт его прямо в `send_file`:

```python
@app.get("/lesson/<int:id>/file")
def download_attachment(id):
    lesson = db.get_lesson(id)
    if lesson is None or not lesson["file_path"]:
        abort(404)
    return send_file(lesson["file_path"], as_attachment=True, download_name=lesson["file_name"])
```

Проверки, что путь остаётся внутри каталога загрузок, нет. Значит цепочка такая:

1. Создать урок, чтобы получить id, который принимает маршрут загрузки.
2. Собрать локальный файл SQLite с той же схемой, где есть этот id и дополнительные строки с `file_path` на нужные файлы.
3. Загрузить его как `/data/uroki.db`, подменив живую базу.
4. Читать `/lesson/<доп. id>/file` по каждой строке.

Так читаются `/etc/passwd`, `/entrypoint.sh`, исходники приложения, всё, что доступно пользователю `app`. Заодно появляется надёжный признак того, что прочитать нельзя: отсутствующий файл даёт 500 (исключение `send_file` не превращается в 404), поэтому 500 на `/flag.txt` означает «есть, но запрещено», а не «нет файла».

Зачем этот шаг: подмена базы превращает запись в произвольное чтение, а чтение и открывает `chmod 0000`.

## 3. Почему флаг остаётся недоступным

`/flag.txt` принадлежит `app` с режимом `0000`. Открытие падает с `EACCES` даже для владельца, потому что владение даёт право менять режим, а не обходить его. `send_file` бросает исключение, эндпоинт отвечает 500.

Отсюда два следствия. Опубликованный одношаговый эксплойт, который только подменяет базу и просит `/flag.txt`, заканчивается тремя 500 и без флага. И второй шаг не может быть «читать сильнее»: нужно изменить режим, а для этого нужен код от `app`.

Зачем этот шаг: понимание детали про владельца превращает неудачное чтение в понятную следующую цель.

## 4. Исполнение кода через расписание beat

`supervisord.conf` запускает воркер от `app` с `directory=/data`:

```text
command=celery -A app.tasks worker -B --concurrency=2 -l info
```

В `tasks.py` задан `beat_scheduler="app.scheduler:JournalScheduler"`, а `JournalScheduler` наследует `PersistentScheduler` из Celery, который держит расписание в базе `shelve` с именем `celerybeat-schedule` в рабочем каталоге, то есть в `/data`. `shelve` хранит pickle.

`web.py` вызывает `ops.apply_schedule_changes()` при создании, правке и удалении урока, а эта функция запускает `supervisorctl restart celery`. Значит рестарт вызывается из веб-интерфейса когда угодно.

План собирается сам:

1. Собрать базу `dbm.dumb` с одним ключом, чей pickle вызывает `os.system`.
2. Загрузить её тем же приёмом с абсолютным путём как `/data/celerybeat-schedule.dir` и `/data/celerybeat-schedule.dat`.
3. Создать любой урок, что перезапускает воркер.
4. Beat при старте открывает shelve, разбирает pickle, и команда выполняется от `app`.

Payload делает две вещи, чтобы результат пережил отказ одного из путей чтения:

```sh
chmod 0644 /flag.txt
cp /flag.txt /data/uploads/flagcopy.txt
```

Зачем этот шаг: владелец файла с режимом `0000` всё равно может сделать `chmod`, поэтому RCE нужно только от нужного пользователя, а не от root.

## 6. Тупики

- Читать `/flag.txt` сразу после подмены базы: 500 из-за режима.
- Перебирать другие пути флага: `/flag`, `/app/flag.txt`, `/data/flag.txt` дают 500, а `/entrypoint.sh` показывает, что файл один.
- Писать в `/app`: в образе каталог `0555` и принадлежит root.
- Класть python-модуль в путь импорта: `celery` запускается из `/usr/local/bin`, рабочий каталог в `sys.path` не попадает, а `/app` только для чтения.

## 7. Выводы

- Файл с режимом `0000` не защищён от владельца: владение это право менять права, и этого достаточно, чтобы просить исполнение кода вместо чтения.
- Брокеры и планировщики, сохраняющие состояние через pickle, являются поверхностью исполнения кода; здесь файл расписания лежит в каталоге, куда может писать веб-приложение.
- 500 вместо 404 на маршруте скачивания это сигнал, а не шум: он отделил «нет файла» от «запрещено» и указал на режим.
- Починка только пути загрузки оставит планировщик записываемым; ограничивать надо оба пути, а каталог данных не должен быть доступен веб-процессу на запись.

Одним абзацем: абсолютное имя проходит `clean_name`, и `os.path.join` записывает загруженный файл поверх `/data/uroki.db`, из-за чего подготовленная база превращает маршрут скачивания в произвольное чтение файлов; оно показывает, что `/flag.txt` принадлежит `app` с режимом `0000`, поэтому тем же примитивом в расписание Celery beat в `/data` кладётся pickle-payload, создание урока перезапускает воркер, payload делает chmod флага, и дальше флаг скачивается обычным образом.
