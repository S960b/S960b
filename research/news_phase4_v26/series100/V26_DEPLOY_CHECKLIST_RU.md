# NEWS Intelligence v2.6 — внедрение и откат (план исполнения)

**Состояние: подготовлено, НЕ УСТАНОВЛЕНО, НЕ АКТИВИРОВАНО.**
Этот план не разрешает вызовы модели или сделки. Версия v2.5 остаётся нетронутой.

## Точка назначения

- Код в отдельной проверенной копии ветки `news-v25-next100-chatgpt-20261119`
  по зафиксированному SHA после результатов тестов.
- Данные только `~/.local/share/news-phase4-v26-series100/`:
  `rss.sqlite`, `rss_meta.sqlite`, `rss_raw/`, `series.sqlite`,
  `binance_raw/`, `attestation.jsonl`, `frozen-*.json`.
- Протокол `series100/V26_SERIES_PROTOCOL.md`. Новый бюджет **100/300**,
  без смешивания с исходной BTC-only серией.
- CLI `series100/v26_series_runner.py`: по умолчанию только status;
  `--poll` только RSS; `--label` только закрытые свечи;
  `--execute` **отказывает без отдельной подписанной владельцем активации**
  и отсутствующего по умолчанию `V26_TRIGGER_ENABLED`.
- Отдельный `series100/v26_monitor.py` для чтения статистики. Никаких
  изменений действующего `news-monitor.service` до завершения приёмки.

## Порядок установки

1. **Offline check.** Точная ветка/SHA, `git status --porcelain` пустой,
   `compileall` нового Python и изменённых модулей. Запустить:
   `rss14_adapter.py`, `rss_sidecar.py`, `rss_noise_filter.py`,
   `v26_symbol_market.py`, `v26_market_provenance.py`,
   `v26_feed_pipeline.py`, `v26_asset_binding.py`,
   `v26_series_runner.py --selftest`, `v26_monitor.py --selftest`,
   `test_v26_e2e.py`. Сеть/DeepSeek заблокированы в тестах.
2. **Regression.** Прогнать все существующие release `test_v2*.py`,
   `test_v24*.py` без исключений; точное число пройденных,
   пропущенных и отклонённых тестов зафиксировать.
3. **Отдельная копия БД.** Убедиться, что нет изменений live v2.5:
   `series_claims=0`, `series_invocations=0` для будущей v2.6, прежний
   `news-series100-trial.timer` остаётся inactive/disabled.
4. **Один реальный RSS-only canary poll.** Только после offline PASS и отдельно
   разрешённого безмодельного теста выполнить `--poll` на изолированной копии.
   Проверить 14 ответов, ошибки HTTP, 1 GET на источник при отсутствии
   исключений транспорта, 0 вызовов DeepSeek, целостность RSS-архива/sidecar,
   и фактическую продолжительность полного опроса.
5. **Нагрузка/латентность.** Для crypto действует максимум **120 секунд**,
   поэтому собрать `first_observed - published`, `decision - first_observed`
   по источникам. Цель: RSS-опрос не реже 60 секунд и обработка важной новости
   до лимита 120 секунд. Если цикл в реальности слишком медленный — STOP,
   исправить расписание/зависания, не увеличивая окно ради PASS.
6. **Развёртывание только отдельной службы** RSS-опроса и read-only монитора:
   названия, каталоги и права должны не конфликтовать с v2.5. В systemd
   ограничить параллельные экземпляры `--poll` (сервис-одиночка).
   `--execute`-таймер НЕ СОЗДАВАТЬ/НЕ ВКЛЮЧАТЬ на этом этапе.
   Проверить после установки ошибки и откат.
7. **Независимый аудит** всей связки: все три market symbols, промпты N/NM/M,
   полная изоляция M, запрет задней датировки, rate limit/429, dedup,
   immutable raw witness, квоты 100/300, неизвестный исход вызова,
   4h labels по закреплённому символу, проверка crash/restart.
8. **Отдельное GO владельца** на model paper trial после PASS. Activation
   должна быть привязана к конкретным SHA протокола и сборки и не должна
   переиспользовать BTC-only activation. До GO 0 вызовов.
9. **Постзапускной контроль:** счётчик `claimed/sealed/calls_reserved`,
   три тикера отдельно, `pending/labelled/censored` после 4h, event witnesses,
   важные RSS-ошибки, нет настоящих сделок.

## Недопустимые действия

Не перезаписывать старые БД, снапшоты, аттестацию и логи; не менять или
перезапускать существующие рабочие v2.5 службы по привычке. Не подменять
критическую RSS-новость техническим временем загрузки, не переписывать
`first_observed` и не расширять лимит свежести. Не проводить автоматически
пробную тройку модели даже при синтаксически успешной установке.

## Откат

- При проблеме остановить/отключить **только новые v2.6** службы.
- Сохранить v2.6 БД, frozen/evidence и журналы для аудита без удаления.
- Проверить, что прежние v2.5 collector и monitor работали без изменений.
- Временные изолированные test-fixture каталоги можно убрать после архивации
  результатов; настоящие свидетельства не удалять.
- Для восстановления нового кода — откатиться на предыдущее проверенное SHA
  в отдельной копии, не редактируя исторические наблюдения.

## Перезапуск агента МТ

**Пока не нужен.** МТ забирает коммиты в изолированную копию. После успешных
тестов может понадобиться запуск новой systemd user service, но не
перезагрузка всего МТ/плагина. О необходимости скажем только по факту
несовместимости загруженного кода или статуса службы.
