# Hermes Chat Bridge

Мост между ChatGPT и локальным AI-агентом MultiTool (MT / Hermes) на компьютере.

ChatGPT формулирует задачи, пишет код, анализирует результаты и принимает решения. Локальный агент работает с файлами, терминалом и установленными инструментами, выполняет поручения и возвращает отчёты. Мост обеспечивает обмен сообщениями, сохранение истории и контроль того, чей сейчас ход.

## Как устроен обмен

```text
ChatGPT
  │ MCP-инструменты: создание задачи, индекс, состояние
  │ проверенная запись сообщения через Git
  ▼
Git-диалог: одна задача = одна ветка dialogs/<task_id>
  ├── task.json
  ├── state.json
  └── messages/<seq>.<actor>.json
  │
  ▼
Локальная authority → MT Git Inbox → сессия MultiTool
                                  │
ChatGPT ← отчёт в том же Git-диалоге
```

Сообщения сохраняются последовательно. Система проверяет идентификатор задачи, очередность ходов и состояние публикации. Доставка нового сообщения в локальную сессию — отдельный этап: запись в Git сама по себе не означает, что агент уже приступил к выполнению.

## Возможности

- Обмен задачами и результатами без ручного переноса текста между агентами.
- Независимая история каждой задачи; чтение последних сообщений и проверка состояния.
- Локальный Taskboard со списком задач и историей сообщений (обычно `http://127.0.0.1:8787`).
- Контроль доставки через очередь MT Inbox, а также обработка неоднозначных исходов без слепого повторения исполнения.
- Работа как с отдельными заданиями, так и с длительными проектами в рамках одного диалога.

## Технические границы

В используемом интерфейсе доступен набор MCP-инструментов `dialog_create`, `dialog_creation_status`, `dialog_list`, `dialog_index`, `dialog_health` и `dialog_notice`. Их фактический состав нужно проверять в начале новой сессии. `dialog_index` возвращает метаданные, а не текст сообщения. `dialog_notice` подтверждает наблюдение существующей публикации, а не создаёт сообщение и не подтверждает доставку агенту.

Git используется как журнал задач; локальные процессы, авторизация, состояние MT и рабочие окружения существуют отдельно. Нельзя восстанавливать живую систему простым запуском исторических скриптов из `legacy/`.
