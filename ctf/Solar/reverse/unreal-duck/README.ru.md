# Невероятная утка (reverse)

Задача про игру на Unreal Engine 5.7. Дано: Windows-сборка клиента, папка контейнеров контента,
лаунчер и действующий многопользовательский сервер. Исходников проекта нет. Флаг приходит
наградой после правильного прохождения игровых маршрутов.

Что в сборке:

- `UnrealDuckClient.exe` 167 424 байта, это лаунчер, он только запускает основной процесс.
- `UnrealDuck/Binaries/Win64/UnrealDuckClient-Win64-Shipping.exe` 143 861 760 байт, здесь
  основной код игры. Его SHA-256 `d0aff10fbd7e980dc9edcaa8cc95d232a37b11c7eb977ad9e66784cec532b802`,
  все адреса в разборе относятся именно к этой сборке.
- `UnrealDuck/Content/Paks/` с контейнерами `global.utoc`, `global.ucas`,
  `UnrealDuck-WindowsClient.utoc`, `UnrealDuck-WindowsClient.ucas` и
  `UnrealDuck-WindowsClient.pak`. Индекс IoStore начинается со шестнадцатибайтовой сигнатуры
  `-==--==--==--==-`, дальше по смещению `0x10` идёт версия 8, по `0x14` размер заголовка 144.

Опорные факты:

- Контент упакован в IoStore со сжатием Oodle: 2126 chunk, 504 пакета. В pak 1662 записи, но
  игровых ассетов там нет: только движковые конфиги, кэш шейдеров и `AssetRegistry.bin`.
- Пакеты имеют `legacy: -9` и `uses_unversioned_properties: True`, то есть это UE5 и имена
  свойств в файлы не записаны.
- Игровая карта в сборке одна, тренировочная арена `Lvl_ThirdPerson`. Второй файл карты,
  `Lvl_MainMenu`, это экран меню, а меню уровнем не является.
- Логика в нативном коде. В строках исполняемого файла есть RPC-функции
  `ServerPushCheatLetter`, `ServerRecordFrame`, `ClientReceivePayload` и ещё несколько.
  В клиентской сборке серверные RPC пустые, проверку выполняет серверная сборка, которой в
  архиве нет, но клиент сам считает контрольное значение маршрута.
- Состояние контроллера игрока: `PC+0x7B0` упакованные символы, `PC+0x7C0` счётчик
  обработанных маршрутов, `PC+0x7C8` текущий номер маршрута, `PC+0x7E0` и `PC+0x804`
  промежуточные состояния, `PC+0x808` массив букв, `PC+0x810` их количество, `PC+0x800`
  блокировка ввода.
- Проверка кода локальная: три записи профиля по 28 байт и функция над ними. Перебор `26^5`
  даёт единственные решения `ILOVE`, `DUCKS`, `ALOTT`, то есть `I LOVE DUCKS A LOT`.
- Коды вводятся штатными событиями клавиатуры, Frida служит только монитором состояния.
  Награда приходит картинкой через `ClientReceivePayload`.

Файлы:

- `scripts/duck_extract.sh` - распаковка IoStore и pak
- `scripts/unrealduck_utoc_index.py` - чтение индекса IoStore и списка путей
- `scripts/duck_map_layout.py` - разбор структуры классического пакета Unreal
- `scripts/duck_scan.py` - поиск интересных строк в контенте и в исполняемом файле
- `scripts/duck_smc_decode.py` - декодирование трансформаций блоков уровня
- `scripts/duck_umap_probe.py`, `scripts/duck_umap_fixmap.py` - исследование структуры `.umap`
- `scripts/duck_frida_guarded.py`, `scripts/duck_frida_guarded.js` - защищённый перехват
  получателя награды
- `scripts/duck_capture_payload.py` - простой перехватчик полезной нагрузки
- `scripts/duck_solve_corrected.cpp` - локальный перебор кодов
- `scripts/duck_auto_guide.py` - автоматический ввод кодов штатными событиями клавиатуры
- `scripts/duck_dump_profile.py` - снятие профиля маршрутов из памяти и сверка констант
- `assets/` - список путей контейнера, список ассетов проекта, вывод перебора

Тяжёлые артефакты (сама сборка и распакованный контент) в репозиторий не копируются.

Полный путь решения описан в `solve.ru.md`.
