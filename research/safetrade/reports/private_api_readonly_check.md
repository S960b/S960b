## 1. Авторизация

Схема (документация OpenWare SDK 2.6):
- `X-Auth-Apikey` — публичный ключ (16 hex);
- `X-Auth-Nonce` — миллисекундный Unix-время UTC, уникален для КАЖДОГО запроса
  (монотонный: два запроса в одну мс получают разные nonce);
- `X-Auth-Signature` — `HMAC-SHA256(secret, nonce + apikey)` hex.

Подтверждено живьём: без заголовков 401 `authz.invalid_session`, с битым
nonce 401 `authz.nonce_expired`, с корректной подписью 200.

## 2. Клиент (исправлено по ревью 2e96fc9)

- **Whitelist GET**: разрешены ТОЛЬКО
  `/trade/public/{markets,depth,trades,tickers}`, `/trade/ping`,
  `/trade/balances`, `/trade/market/orders`, `/trade/market/trades`.
  Любой другой путь (включая `/orders/123/cancel`, который в этом стеке может
  существовать как GET) отклоняется ДО транспорта (`ValueError`) — проверено.
- **Редиректы запрещены**: `HTTPRedirectHandler` переопределён, 3xx = ошибка;
  заголовок API-ключа на другой домен не пересылается.
- **Уникальный nonce**: миллисекунды + строгая монотонность (last+1) — два
  вызова в одну мс дают разные nonce.
- Таймаут 20с, до 3 попыток, 429 → backoff 2/4с; сеть отделена от API-ошибок.
- **Только чтение**: никаких create/cancel/withdraw; торговые пробы не
  выполнялись и не разрешены этим этапом.

Файлы: `scripts/private_api_probe.py` (клиент), `scripts/private_scan.py`
(классификация). Оба — обезличенный вывод.

(только read; trade/withdraw остаются отключёнными). После расширения —
повторная проверка (отдельным заданием; без реальных ордеров).

## 4. Комиссии (уточнено по ревью 2e96fc9)

| Источник | Значение |
|---|---|
| Публичный `GET /api/v2/trade/public/trading_fees` | maker=0.001, taker=0.001 (все рынки) |
| Поля `maker_fee`/`taker_fee` каждого ордера аккаунта | 0.001 / 0.001 (на каждом ордере) |
| Фактические исполнения аккаунта (taker-роль, см. ниже) | 10.00 bps (мин=мед=макс, без разброса) |

**Роль исполнений:** все свои ордера — `type=market`, т.е. все исполнения —
**taker**. Ставка taker = 10 bps подтверждена исполнениями напрямую. Ставка
maker = 10 bps подтверждена полями ордеров `maker_fee` и публичным тарифом,
но живых maker-исполнений на аккаунте нет — помечается как
`confirmed_public_schedule + account_orders_fields`, не как
`confirmed_by_maker_fill`.

**Валюта комиссии** (факты, 21 сделка): PRLUSDT — fee в USDT для ВСЕХ сделок
(и sell, и buy); QUANTUSUSDT — fee в USDT (sell); LTCUSDT — fee в LTC (buy).
Гипотеза ревью «комиссия в получаемой валюте» **НЕ подтверждается**: buy PRL
(получаемая — PRL) имеет fee в USDT, buy LTC (получаемая — LTC) — fee в LTC.
Похоже, валюта привязана к паре (правилам рынка): PRL/QUANTUS — USDT,
LTC — LTC; для полного подтверждения нужны сделки обеих сторон по каждой паре
или ответ биржи. В экономических расчётах (econ/opportunity) комиссия
трактуется в quote-валюте; при расхождении пар с fee в base — поправка.

## 5. Post-only — unverified

Флага post_only в документации Peatio/OpenWare 2.6 не найдено; swagger биржи
недоступен. Пробная заявка вне пересечения стакана останется maker и без
флага — такая проба поддержку не доказывает (ревью 2e96fc9). Статус:
**unverified**; торговые пробы этим этапом не разрешены. Перед ордерным этапом
подтвердить post-only отдельно (у биржи/документации), не предполагая его.
