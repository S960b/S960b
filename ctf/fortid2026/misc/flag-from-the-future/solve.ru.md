# Flag from the Future - разбор (Conway's Game of Life, восстановить текст флага)

## Знакомство с задачей

Задание `Flag from the Future` (Misc, автор ipaljak) даёт один файл: изображение, которое является финальным состоянием Conway's Game of Life. В описании сказано, как формировалось поле:

- скрытый текст растеризовывался шрифтом **DejaVu TTF 2.37**;
- размер шрифта был **целым числом пикселей**;
- каждый пиксель со **светлотой >= 50%** становился живой клеткой;
- автомат выполнял несколько поколений, и получившееся поле - это изображение, которое нам выдали.

Цель: восстановить скрытый текст `FortID{...}`.

То есть описание даёт хороший старт: семейство шрифта (DejaVu), версию (2.37) и правило порога. Осталось найти: точное начертание (обычное/жирное/курсив/моно), точный размер в пикселях, число поколений и сам текст.

## Выбор инструментов (и почему)

Мне нужно было работать с изображением и симулировать клеточный автомат. Что я использовал и почему:

- **Pillow (PIL)** - стандартная Python-библиотека для открытия и рисования изображений. Умеет и читать наш скриншот, и рендерить текст шрифтом TrueType через `ImageFont.truetype`. Я погуглил «python render text to image font» - Pillow первый и самый распространённый ответ.
- **NumPy** - стандартный способ держать изображение как матрицу чисел. Изображение - это просто двумерный массив значений пикселей, а NumPy даёт быстрые операции (`board.sum()`, сравнения, срезы).
- **SciPy** (`scipy.ndimage.convolve`) - классический однострочник для шага «Жизни»: подсчёт живых соседей каждой клетки свёрткой с ядром 3x3, затем применение правил. Этот приём я вспомнил из чтения про клеточные автоматы на Python.

Все три стоят на Kali (или `pip install pillow numpy scipy` в venv).

## Шаг 1. Заглядываем внутрь изображения (маленьким скриптом)

Первое, что я сделал, - посмотрел на пиксели крошечным Python-скриптом: Pillow открывает PNG, NumPy превращает его в матрицу чисел яркости (0 = чёрный, 255 = белый). Это шаг «открыть файл и посмотреть», только для пикселей:

```python
from PIL import Image
import numpy as np

a = np.asarray(Image.open('screenshot.png').convert('L'))  # матрица 3062x288 чисел 0..255
print(a.shape)               # (288, 3062)
print((a < 128).mean())      # доля тёмных пикселей: 0.963
print((a >= 128).mean())     # доля светлых пикселей: 0.037
alive = a >= 128             # бинаризация
print(int(alive.sum()))      # 32724
```

Вывод сказал мне три вещи:

- изображение почти чёрное: 96.3% пикселей тёмные, всего 3.7% светлые. Это ровно то, как выглядит поле «Жизни» - редкие живые клетки на чёрном фоне;
- **бинаризация** - это просто превращение изображения в «либо-либо»: каждый пиксель с яркостью >= 128 (то есть >= 50% от 255, как и сказано в задании) становится 1 (белый, живой), всё остальное - 0 (чёрный, мёртвый). Получается матрица `alive` из 0 и 1;
- подсчёт единиц (`alive.sum()`) даёт **32724 живых пикселя** - первое конкретное число задачи.

Зачем этот шаг приближает нас к флагу: теперь изображение - это числа, с которыми можно вычислять, а не пиксели на экране.

## Шаг 2. Находим период сетки (как нарисованы клетки)

Изображение - скриншот, значит клетки, скорее всего, нарисованы крупнее одного пикселя. Прежде чем что-то симулировать, надо знать шаг сетки: сколько пикселей занимает одна клетка и где зазор.

Метод (снова маленький скрипт): для кандидата периода `p` берём каждый пиксель и смотрим его позицию по модулю `p` по обеим осям - `(y mod p, x mod p)` даёт один из `p*p` «классов остатков». Для каждого класса считаем, какая доля его пикселей живая. Если `p` совпадает с реальной сеткой, живые клетки лежат только внутри области клетки, а остатки зазора пустые.

```python
for p in (6, 7, 8, 10, 12):                      # кандидаты периода
    frac = np.zeros((p, p))
    for ry in range(p):
        for rx in range(p):
            frac[ry, rx] = alive[ry::p, rx::p].mean()   # доля живых по остатку
    print(p, frac.round(3))
```

Только **p = 8** дал чистую картину:

- остатки 0..5 (обе оси): доля живых ~0.091, равномерно - эти 6 строк/колонок и есть тело клетки;
- остатки 6..7: ровно 0 - эти 2 строки/колонки и есть зазор.

Значит, раскладка такая: **клетка 6x6 пикселей**, затем **зазор 2 пикселя**, период 8. И арифметика сходится: `32724 живых пикселя / 36 пикселей на клетку = 909` живых клеток - круглое число, которое станет якорем всех дальнейших проверок.

Зачем этот шаг: теперь мы можем уменьшить скриншот с пикселей до настоящих клеток и получить маленькую бинарную сетку (27x371), которую можно сравнивать с симуляциями.

## Шаг 3. Оцифровываем скриншот в сетку клеток

Я уменьшил: для каждого блока 8x8 клетка живая, если хотя бы один из её 6x6 пикселей живой, затем обрезал пустые поля. Результат: сетка **27x371 с 909 живыми клетками** - сохранена как `evidence/grid_target.png`.

Зачем: теперь у нас есть цель в той же форме, которую даст симуляция, - один бит на клетку.

## Шаг 4. Проверка прямым моделированием (почему не в обратную сторону)

Game of Life **необратим**: много разных начальных полей сходятся в одно состояние, и детерминированного «обратного запуска» нет. Поэтому единственный надёжный метод - прямой: рендерим текст-кандидат, симулируем N поколений, сравниваем с целью.

Каждый шаг поколения (стандартные правила):

```text
neighbors = convolve(board, kernel)          # 3x3, без центра
board = (neighbors == 3) | (board & (neighbors == 2))
```

- мёртвая клетка оживает ровно при 3 живых соседях;
- живая выживает при 2 или 3 живых соседях;
- иначе умирает.

### Как сравнивать две сетки (расстояние Хэмминга)

Вопрос: совпадают ли симулированная сетка и сетка-цель? «Совпадают» здесь значит *в каждой клетке*: живая в обеих, мёртвая в обеих.

Мне нужно было число для «насколько различаются две бинарные сетки», поэтому я погуглил «how to compare two binary images metric» - и стандартный ответ это **расстояние Хэмминга**: посчитать позиции, где две сетки различаются.

Для двух сеток `A` и `B` одного размера оно определяется так:

```text
D = сумма по всем клеткам (x, y) от (A[x,y] != B[x,y])
```

то есть каждая клетка даёт 0, если значения равны, и 1, если различаются; `D` - общее число различающихся клеток. (В Python это ровно `np.count_nonzero(A != B)`.)

Если `D = 0` - сетки идентичны, текст-кандидат ровно тот, что породил изображение задания. Если `D` большое - кандидат неверный. То есть расстояние Хэмминга - это *тест «да/нет»*, который двигает весь поиск в следующем шаге.

## Шаг 5. Находим параметры и текст флага

Дальше поиск. Что я варьирую: начертание шрифта (внутри DejaVu: Sans, Sans Mono, Serif, каждое обычное/жирное), размер шрифта (целое, начиная с малого), число поколений (1..~30), и текст-кандидат (начиная с `FortID{` и расширяя).

Трюк, который делает поиск реальным: формат флага `FortID{...}` фиксирует первые 7 символов. Поэтому я:

1. рендерю `FortID{` + догадку следующего символа(ов) кандидатным шрифтом/размером,
2. симулирую увеличивающиеся поколения,
3. сравниваю число клеток и позиции с целью.

Параметры, которые подошли: **DejaVu Sans Mono Bold, 16 px**. Текст-кандидат, который изначально даёт 1661 живую клетку и после **18** поколений - ровно 909 клеток ровно в позициях цели.

Итерируя посимвольно (каждый новый символ должен сохранять совпадение симуляции с целью), текст складывается в:

```text
FortID{R3al_L1f3_...}   (замаскирован; полное значение воспроизводит 909 клеток / точное совпадение)
```

(Текст - намёк на саму задачу: «Real Life Has No Rewind Button» - у «Жизни» нет перемотки назад, поэтому текст восстанавливают проверкой вперёд.)

## Тупики (что я пробовал сначала)

1. **Запуск автомата назад.** Невозможно: Game of Life необратим; именно поэтому прямая симуляция - единственная надёжная проверка.
2. **Угадывание семейства шрифта.** Первые попытки с DejaVu Sans (пропорциональным) не давали 909 клеток в нужных позициях; подошёл **Sans Mono Bold** (моноширинный, жирный). Моноширинность логична для флага: каждый символ одной ширины, растр регулярный.
3. **Неверное число поколений.** Слишком мало или много - финальное число клеток менялось радикально (поле быстро растёт/сжимается); только 18 дало 909 клеток в раскладке цели.

## Уроки

1. Поле клеточного автомата в изображении - это сетка: найди период (таблицы остатков), уменьши, и только потом думай о тексте.
2. Число живых клеток - отличный якорь: 32724 пикселя / 36 px-на-клетку = 909, а 1661 начальных - 909 после 18 поколений; круглые числа валидируют каждый шаг.
3. Для необратимых автоматов единственная надёжная проверка - прямое моделирование: рендер, симуляция, сравнение - и никогда не пытаться инвертировать правила.
4. Префикс флага `FortID{` фиксирует 7 символов и делает поиск реальным посимвольно.
5. Pillow + NumPy + SciPy - стандартный Python-стек для задач «изображение + клеточный автомат» - экзотика не нужна.
