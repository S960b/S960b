# Traverse: разбор конфигурации FPGA iCE40

[English](solve.md)

## 0. Идея

В архиве `traverse.zip` лежали `traverse.bin` и `run.py`. По расширению `.bin` легко ошибочно принять задачу за реверс обычной программы. На деле конфигурация относится к FPGA iCE40 HX1K. У таких устройств логика задаётся таблицами LUT, регистрами и маршрутизацией, а не машинными инструкциями.

## 1. Начинаем с Python-обвязки

```bash
unzip -l traverse.zip
unzip traverse.zip -d traverse-work
sed -n '1,240p' traverse-work/run.py
file traverse-work/traverse.bin
```

Из `run.py` нужно выяснить границы задачи: что подаётся на вход, что считается результатом и какие ресурсы конфигурации вообще задействованы.

## 2. Распаковываем битстрим

Для iCE40 подходит IceStorm:

```bash
iceunpack traverse-work/traverse.bin > chip.asc
icebox_explain chip.asc > chip.explain.txt
```

`chip.asc` показывает биты конфигурации по тайлам. `icebox_explain` расшифровывает часть конфигурационных признаков. Это ещё не исходный Verilog, но уже можно исследовать логику.

Из анализа было получено около **692 активных логических ячеек** и **ни одной задействованной блочной RAM**. В исследовательском наборе имелись `parse.py`, `unpack_python.py`, `chip.asc`, `active.txt`.

## 3. Как читать такую схему

Я бы не начинал с перебора LUT. Сначала нужно найти выходные пины, использованные Python-обвязкой, а затем проследить связи назад. Для каждого участка записать: входы LUT, её таблицу истинности, регистрационные элементы, обратную связь, соединения с соседними тайлами.

После этого можно объединять маленькие булевы функции в конечный автомат или вычислительный тракт. В отличие от ELF здесь нет обычного `main`, стека вызовов и машинных инструкций.

## 4. Граница сохранившихся данных

Задача Traverse есть в командных сдачах, и решение было подтверждено в чате. Однако в доступных заметках **нет финального флага и последней последовательности действий**, которая его извлекла. Не буду придумывать готовый дамп симуляции. Этот райтап честно покрывает восстановленную часть исследования и показывает, какие файлы нужны для точного окончания.

## 5. Вывод

Самый важный первый шаг был определить аппаратную платформу и получить структурное представление `chip.asc`. После сокращения схемы до активной логики анализ становится технически осмысленным. Для полного повтора ещё требуется исходный архив и финальные заметки решённой сессии.
