# FSenc: исследование заголовка с Argon2id

[English](solve.md)

## 0. Какие данные действительно сохранились

FSenc была задачей с динамическим инстансом, официальной статической раздатки на платформе не было. В итоговом списке флаг принят, но в сохранённых рабочих материалах **нет исходного шифровальщика, `flag.bin`, `a.enc`, восстановленного пароля и успешного вывода расшифровки**. Остались два подробных фрагмента команд `evidence/solve_1.txt` и `solve_2.txt`.

В ходе решения проверяли две конкурирующие гипотезы: 44 байта после 12-байтного префикса файла можно использовать непосредственно как ключ и nonce ChaCha20-Poly1305 либо эти 44 байта являются результатом Argon2id от пароля. Обе проверки есть в логах, **но их ответы не сохранились**. Поэтому не станем объявлять одну гипотезу доказанной.

## 1. Предполагаемый формат файла

В сохранённом скрипте:

```python
f = open('flag.bin', 'rb').read()
hdr = f[12:56]
body = f[56:]
key, nonce = hdr[:32], hdr[32:44]
```

Предположение о структуре:

```text
0              12             56                 конец
+--------------+--------------+---------------------+
| magic/prefix | header 44 B  | ciphertext + tag    |
+--------------+--------------+---------------------+
               | key 32 | nonce 12 |
```

Это не спецификация шифровальщика, а фактическая разметка, с которой работал исследователь. Её можно подтвердить только настоящим файлом или исходниками программы.

Первая попытка:

```python
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305
pt = ChaCha20Poly1305(key).decrypt(nonce, body, None)
```

Проверка тега AEAD сама по себе полезна: успешная расшифровка подтверждает совпадение ключа, nonce и шифртекста. В скрипте предусмотрены сообщения `PLAINTEXT:` и `fail:`, однако вывод не сохранён. Утверждать, что ключ лежал в файле открытым текстом, нельзя.

## 2. Вторая гипотеза: Argon2id

Следующая команда генерирует `crack.py`, сравнивающий Argon2id каждого словарного кандидата с теми же 44 байтами:

```python
from argon2.low_level import hash_secret_raw, Type
magic = bytes.fromhex("4ca36c80fff763eb2be4224f")
salt = magic + magic[:4]
target = open("flag.bin", "rb").read()[12:56]
derived = hash_secret_raw(
    password, salt, time_cost=2, memory_cost=19456,
    parallelism=1, hash_len=44, type=Type.ID
)
```

Соль — 16 байт: 12-байтный magic плюс повторённые первые четыре байта. Результат KDF — 44 байта, то есть ровно длина исследуемого поля. Если поле действительно содержит KDF-вывод, пароль можно проверять по словарю **офлайн**.

Сохранённый запуск:

```sh
timeout 115 python3 -u crack.py /usr/share/wordlists/rockyou.txt 30000
```

Использовано восемь процессов, `chunksize=64`, ограничение на 30 тысяч слов и таймаут 115 секунд. Но такой запуск не доказывает, что все 30 тысяч паролей успели проверить: Argon2id намеренно тяжёлый. Строки `FOUND:` с конкретным паролем в архиве нет.

## 3. Контрольный файл с известным паролем

Отдельно проверяли `testpass`:

```python
h = hash_secret_raw(b"testpass", salt, 2, 19456, 1, 44, Type.ID)
key, nonce = h[:32], h[32:]
data = open("a.enc", "rb").read()
print(ChaCha20Poly1305(key).decrypt(nonce, data[56:], None))
```

Смысл теста: проверить, что полученные через Argon2id ключ/nonce действительно расшифровывают тестовый файл с известным паролем. Но самого `a.enc` и результата в архиве нет, поэтому положительный итог не доказан.

## 4. Воспроизводимый диагностический скрипт

Добавлен [scripts/inspect_fsenc.py](scripts/inspect_fsenc.py), повторяющий три проверки на переданном локальном файле:

```sh
python3 scripts/inspect_fsenc.py flag.bin --direct
python3 scripts/inspect_fsenc.py flag.bin --password testpass
python3 scripts/inspect_fsenc.py flag.bin --wordlist /usr/share/wordlists/rockyou.txt --limit 30000
```

Скрипт не содержит флага и не притворяется полным солвером, пока отсутствует исходный шифртекст.

## 5. Подтверждения и пробелы

| Утверждение | Подтверждение |
|---|---|
| Заголовок исследовали по смещению 12 и длине 44 байта | Да, лог |
| 32 байта для ключа и 12 для nonce | Да, лог |
| Argon2id: t=2, m=19456, p=1, выход 44 байта | Да, лог |
| Соль: 12 байт magic + 4 начальных байта | Да, лог |
| Словарь: максимум 30000 кандидатов, 8 процессов, 115 секунд | Да, лог |
| Прямое декодирование файла успешно | **Нет вывода** |
| Пароль найден через Argon2id | **Нет вывода** |
| Флаг принят платформой | Итоговая запись о результате |

## 6. Выводы и незакрытый вопрос

Чтобы завершить восстановление честно, нужен `flag.bin`, код шифровальщика или исходный терминальный вывод. До этого ни один из способов нельзя выдавать за точно сработавший.

Если ключ сохранён в заголовке без защиты, это критическая утечка. Если KDF-результат от слабого пароля лежит открыто, возможна проверка пароля офлайн. В обоих случаях важно аутентифицировать заголовок и не строить криптографию на слабом секрете.
