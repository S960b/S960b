## Что в задаче

Входное изображение - финальное состояние Conway's Game of Life. В описании задачи прямо сказано, как формировалось поле: текст флага растеризовывался шрифтом DejaVu TTF (версия 2.37) целочисленным размером в пикселях, и каждый пиксель со светлотой >= 50% становился живой клеткой. Цель - восстановить скрытый текст `FortID{...}`.

То есть описание само даёт семейство рендера (DejaVu), версию (2.37) и правило порога (>= 50%); найти остаётся точное начертание, точный размер, число поколений и сам текст.

Правила «Жизни» (что я использовал):

- мёртвая клетка оживает ровно при 3 живых соседях;
- живая клетка выживает при 2 или 3 живых соседях;
- иначе клетка умирает.

Динамика необратима: нельзя «запустить автомат назад» и получить исходное поле. Поэтому подход - прямое моделирование: рендерим текст-кандидат, симулируем N поколений, сравниваем с изображением.

## Решение в двух словах

1. Оцифровано изображение задания `screenshot.png` (3062x288) в сетку клеток: период 8 px (клетка 6x6 + зазор 2); 32724 живых пикселя = 909 клеток x 36 px на клетку.
2. Построена сетка «один бит на клетку»: 27x371, 909 живых клеток (`evidence/grid_target.png`).
3. Параметры найдены перебором «рендер + симуляция»: DejaVu Sans Mono Bold, 16 px, 18 поколений.
4. Текст флага отрендерен белым по чёрному, порог >= 128, 18 поколений:
   - начальных живых клеток: 1661, поколений: 18, результат: 909.
5. Сравнение результата симуляции с оцифрованным скриншотом: **mismatching cells: 0, exact match**.

Полный разбор - в [`solve.md`](solve.md).

## Воспроизведение

```bash

pip install pillow numpy scipy
python3 scripts/flag_from_the_future_verify.py --out /tmp/life18.png --target evidence/grid_target.png
```
