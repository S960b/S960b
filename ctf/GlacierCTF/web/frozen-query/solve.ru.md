# Frozen Query — обход WAF через двойной gzip и кэш аудитора

[English version](solve.md)

**Происхождение сведений:** пользователь включил задачу в список принятых платформой. В найденном старом диалоге сохранилось только упоминание `VERIFY_OK`, без самого успешного запроса или флага. Поэтому конкретный механизм восстановлен по **публичному техническому райтапу другого участника**: https://dua2z3rr.github.io/posts/Frozen-Query-Walkthrough/ . Это не утверждение, что исходные команды пользователя были в точности такими же.

## Устройство

Flask-приложение обрабатывает метод `QUERY` для `/api/bulletin`; закрытая запись `summit` содержит флаг. Встроенный аудитор со своим `AUDIT_TOKEN` каждые **5 секунд** запрашивает `summit` с полями `level,note,flag` и `window=int(time.time()//30)`. Кэш хранит статус, заголовки и тело ответа **30 секунд**.

Ключ кэша — SHA-256 от пути, нормализованного Content-Type, Accept и канонического JSON (ключи сортируются). **Проверка прав не участвует в ключе**. Если повторить запрос аудитора без токена, можно получить приватный уже закэшированный результат — но надо преодолеть WAF.

## Два декодирования против одного

WAF запрещает тело с текстом `flag`. На одну gzip-обёртку он вызывает `gunzip`, обнаруживает `flag` и отвечает 403. Однако `waf_allows` удаляет **только один** слой сжатия, тогда как основной `decode_content` обрабатывает **каждый** элемент `Content-Encoding`.

Отправляем тело `gzip(gzip(JSON))` и заголовок `Content-Encoding: gzip, gzip`. WAF получает после первой распаковки всё ещё сжатые байты, не видит ключ `flag` и пропускает запрос. Основной обработчик распаковывает оба слоя, получает JSON, совпадающий с запросом аудитора, и выполняет **HIT его приватного кэша**.

Необходимо сохранить заголовки `Content-Type: application/vnd.glacier.bulletin+json`, `Accept: application/json` и точное окно `time.time()//30`. Запрос повторяется несколько секунд, пока аудитор не успеет положить результат.

## Воспроизведение

[scripts/solve.py](scripts/solve.py) — **вновь написанный солвер по реконструированной технике**, а не сохранённый оригинальный скрипт. Требует `requests` и явно заданный URL собственного CTF-инстанса. Для проверки победы смотрим HTTP 200, `X-Cache: HIT` и поле `flag`. В локальной версии может лежать `gctf{FAKE_FAKE_FAKE_FAKE_FAKE_FAKE}`; это **не настоящий флаг соревнования**.

## Исправление ошибки

Нужно полностью распаковывать тело **до WAF**, затем проверять именно канонизированную структуру, которую увидит приложение; кэш приватных ответов следует изолировать по правам либо не кэшировать вообще.
