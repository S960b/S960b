# FSenc: ключ ChaCha20-Poly1305 лежал в заголовке

[English](solve.md)

## 1. Разбор формата

FSenc применяет Argon2id для получения криптографического материала и ChaCha20-Poly1305 для шифрования. По отладке и экспериментам с известным паролем восстановлен формат файла:

```text
байты  0..11  : magic, 12 байт
байты 12..43  : ключ ChaCha20-Poly1305, 32 байта
байты 44..55  : nonce, 12 байт
байты 56..конец : шифртекст и 16-байтный тег аутентификации
```

Поле `12:56` содержит 44 байта, полученных из пароля, но **они же открытым текстом записаны в зашифрованный файл**. Поэтому для расшифровки готового файла подбор пароля не нужен.

## 2. Как распознали ключ

При одном и том же пароле первые 44 байта заголовка совпадали у файлов с разным содержимым. Отладка `argon2::Argon2::hash_password_into` и контрольный расчёт позволили определить параметры:

```text
Argon2id(password, salt=magic || magic[:4],
         time_cost=2, memory_cost=19456 KiB,
         parallelism=1, output_len=44)
```

Это объяснило детерминированность поля. Словарные попытки стали не нужны: первые 32 байта поля — готовый ключ, следующие 12 — nonce.

## 3. Успешная команда и результат

Исходный журнал содержит выполненный Python-код:

```python
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

data = open("flag.bin", "rb").read()
header = data[12:56]
key, nonce = header[:32], header[32:44]
plaintext = ChaCha20Poly1305(key).decrypt(nonce, data[56:], None)
print("PLAINTEXT:", plaintext)
```

Фактический вывод:

```text
key   aa1ac2b4ea02d933d65a9c20d8a116f00e3d1094d03cd9d19cb75a9da4b399dd
nonce 8d3b427242a42d5c0df5e60f
PLAINTEXT: b'PP{f1l3_3ncrypt10n_1s_h4rd::A1bk0dIsUfPL}\n'
```

**Флаг принят платформой.** Аналогичное действие реализовано в опубликованном [scripts/inspect_fsenc.py](scripts/inspect_fsenc.py):

```bash
python3 scripts/inspect_fsenc.py flag.bin --direct
```

Режимы поиска пароля оставлены для изучения формата, но в успешной цепочке не использовались.

## 4. Почему это уязвимость

Даже корректный ChaCha20-Poly1305 не защищает шифртекст, если ключ лежит рядом с ним. В правильно устроенном формате хранят публичную соль и nonce, а ключ повторно получают из пароля при открытии файла. Также обязательны контроль nonce и аутентификация метаданных.
