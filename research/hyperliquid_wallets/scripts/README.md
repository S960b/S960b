## Ошибка и исправление

В `analyze.py` поле `fee_sign_convention` трактует знак **наоборот**: там положительная комиссия ошибочно названа maker rebate. В исходном файле ошибка сохранена ради подлинности истории. **Не использовать** его финансовые агрегаты или "win rate" для оценки стратегий.

Верно: `fee > 0` — комиссия/расход, `fee < 0` — rebate/кредит; результат только по полученным исполнениям: `sum(closedPnl) - sum(fee)`. Именно так считает `corrective_audit.py`, причём на основе `Decimal`.

## Ограничения воспроизведения

- Сырые `raw_fills.json`, снимки позиций и закрытые ledger-файлы в публичный репозиторий **не включены**. Поэтому offline-корректор не запускается из коробки; он ожидает локальный файл по историческому пути `/home/kali/research/hyperliquid-public-wallet-audit-v1/raw_fills.json`.
- `collect_fills.py` выполняет публичные POST к **info endpoint** Hyperliquid, не к exchange/order; самостоятельно не торгует. Запуск может создавать файлы с адресами и историей **публичных** кошельков в текущем каталоге. Проверяйте политику хранения/публикации данных самостоятельно.
- 2 000 fills в ответе — лимит страницы, а не доказательство полной истории. 500 funding-записей тоже не покрывают обязательно все 7 суток. Без постраничного извлечения история неполна.
- Нельзя считать количество прибыльных fills количеством успешных законченных позиций или вычислять доходность и просадку кошелька по одному частичному окну.
