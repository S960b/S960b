# Sticker Booth - UAF через путаницу счётчика ссылок, подмена файла

- **Платформа:** FortiD CTF 2026
- **Категория:** Pwn
- **Автор:** ipaljak
- **Очки / Решения:** 113 очков, 196 решений
- **Дата:** 2026-10-09
- **Remote:** `sticker-booth-<...>.inst18.ctf.fortid.com:1337` (TLS/ncat, закрыт после события)
- **Флаг:** `FortID{...}` (замаскирован)
- **Бинарь:** `chall` (x86-64, статически слинкован, без PIE, не stripped) + инструкция `recipe_docs.md`, `assets/`
- **Описание (официальное):** "A place where you can safely customize your stickers and print them out!"

Конструктор стикер-листа, читающий команды из stdin. Комбинируются два бага: фильтр `mono` рисует H+1 строк (только-зануляющий off-by-one в соседний блок пула), а `caption` дедуплицирует одинаковые тексты, из-за чего два элемента делят один буфер со счётчиком ссылок. Зануление счётчика освобождает общий буфер, пока устаревший элемент всё ещё указывает на него (UAF); перевыделение этого блока контролируемым upload'ом и builtin сразу после сливают случайный booth_ticket через контролируемый fwrite. Второй UAF затем подставляет поддельный builtin-заголовок (тип 2, валидный тикет, путь "flag.txt"), и висячий элемент попадает в ветку открытия файла `print` - флаг вываливается.

Файлы:

- `solve.md` - полный ход решения, включая dead ends (английский)
- `solve.ru.md` - тот же ход решения на русском (рабочая копия)
- `scripts/proof_sb.py` - локальный двухфазный proof (лик тикета, подмена пути)
- `scripts/solve.py` - та же цепочка по TLS для remote-инстанса
