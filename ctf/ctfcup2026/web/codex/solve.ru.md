# Codex: как прочитать приватную заметку бота

[English](solve.md)

## 0. Что дано

Это небольшое веб-приложение для чтения Библии с заметками. Бот с правами администратора хранит флаг приватной заметкой на странице `matthew.7`, и видна она только внутри его собственного scope.

В `codex.zip` есть всё нужное: `bot.js` показывает, как заметка создаётся, `server.js` показывает фильтрацию, `public/app.js` показывает, что может браузер.

Два вопроса решают задачу: куда пишется заметка и какой секрет нужен, чтобы прочитать её обратно.

## 1. Как пишет бот

`plant(origin)` в `bot.js` коротка настолько, что её можно привести целиком:

```js
await page.goto(`${origin}/${BOT_UUID}`);
await page.evaluate(async (uuid, flag) => {
  const list = await fetch(`/api/comments?page=matthew.7&scope=${uuid}`).then((r) => r.json());
  if (!list.some((c) => c.author === 'admin' && c.text === flag)) {
    await fetch('/api/comments', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ page: 'matthew.7', author: 'admin', text: flag, anchor: 7, scope: uuid }),
    });
  }
}, BOT_UUID, flag());
```

Отсюда три факта. Заметка всегда попадает на `matthew.7`, всегда с `author: 'admin'` и всегда со `scope`, равным `BOT_UUID`. Ничего из запроса к `/api/visit` на это не влияет, и это первое, что стоит проверить, прежде чем изобретать эксплойт.

`BOT_UUID` в этой версии это `process.env.BOT_UUID || 'cccccccc-cccc-4ccc-8ccc-cccccccccccc'`. Значение по умолчанию и есть уязвимость: деплой переопределяет `FLAG`, но не UUID.

## 2. Чем закрыто чтение

В `server.js` обработчик `GET /api/comments` фильтрует по странице и scope:

```js
if (!PAGE_RE.test(page) || (scope && !UUID_RE.test(scope))) return json(res, 400, ...);
return json(res, 200, comments.filter((c) => c.page === page && (c.scope || '') === scope) ...);
```

То есть заметка отдаётся только при точном совпадении scope. `GET /api/comment/:id` ведёт себя так же, а id это `randomUUID`, его не перебрать. `POST /api/comments` принимает любой scope, поэтому свои заметки создать можно, а узнать чужой нельзя.

В этом ловушка: при неизвестном UUID заметка существует, но недоступна, и пути перебора нет. Задача решается только если `BOT_UUID` остался документированным значением по умолчанию.

## 3. Цепочка

С дефолтным UUID всё сводится к трём запросам:

```bash
HOST=<host>
UUID=cccccccc-cccc-4ccc-8ccc-cccccccccccc
curl -s "$HOST/api/comments?page=matthew.7&scope=$UUID"           # сначала пусто
curl -s -X POST "$HOST/api/visit" -H 'Content-Type: application/json' \
     -d "{\"url\":\"$HOST/$UUID\"}"                              # будим бота
curl -s "$HOST/api/comments?page=matthew.7&scope=$UUID"           # заметка с флагом
```

Первый ответ пуст, визит занимает несколько секунд, потому что бот реально поднимает браузер и создаёт заметку, второй ответ возвращает её текст.

Почему поле `url` тут не помогает: `POST /api/visit` оставляет от присланной ссылки только путь и query, пересобирает её на своём origin, а `plant()` всё равно использует собственный `BOT_UUID`. Направить бота на другую страницу можно, но флаг от этого не переедет.

`scripts/solve_codex.py` делает эти шаги и печатает текст заметки:

```bash
python3 scripts/solve_codex.py https://<host>
```

## 4. Результат

Формат флага `ctfcup{se3k_and_y3_shall_f1nd_<16 hex>}`, в репозитории скрыт как `ctfcup{...}`. Шестнадцатеричный суффикс выдаётся под конкретный деплой: два инстанса во время соревнования вернули разные суффиксы при одинаковом префиксе, поэтому значение надо читать с того инстанса, который решаешь.

## 5. Тупики

- Утащить UUID через тело заметки не выйдет: `app.js` рендерит текст как HTML, но страница отдаёт `Content-Security-Policy: script-src 'self'`, поэтому инлайн-обработчики и инлайн-скрипты не выполняются.
- Заставить бота сходить на чужой origin не выйдет: сервер пересобирает ссылку на своём origin.
- Перебирать UUID бессмысленно: пространство 122 бита, а id заметки это отдельный случайный UUID.

## 6. Что исправил вариант Revenge

Более сложная версия `codex-revenge.zip` генерирует `BOT_UUID` через `crypto.randomUUID()` при старте процесса и добавляет cookie `botpass`, которая дополнительно закрывает `GET /api/comment/:id` и `PUT` для заметок `admin`. Те же три запроса там возвращают пустой список, потому что заметка пишется в scope, который удалённо не узнать. Это стоит помнить, чтобы не считать солвер сломанным: первую версию он решает по устройству задачи.

## 7. Выводы

- Прежде чем атаковать, прочитать, куда пишется секрет и какой ключ его охраняет.
- Значение по умолчанию в исходниках становится уязвимостью только если деплой забыл его переопределить; здесь забыл.
- Проверять поведение деплоя, а не доверять исходникам: один пустой `GET` сразу говорит, на месте ли дефолт.

Одним абзацем: бот кладёт флаг заметкой администратора на `matthew.7` со `scope`, равным своему UUID, который падает в захардкоженный дефолт, потому что деплой переопределяет только флаг; чтение этого scope через `/api/comments` после `/api/visit` возвращает заметку, а суффикс флага у каждого деплоя свой.
