# String Peek & Poke - OOB-индекс на std::string, порча ctype, execve

- **Платформа:** FortiD CTF 2026
- **Категория:** Pwn
- **Очки / Решили:** (очки/решившие не зафиксированы в рабочей папке)
- **Дата:** 2026-10-10
- **Remote:** `string-peek-and-poke-<...>.inst17.ctf.fortid.com:1337` (TLS/ncat, закрыт после ивента)
- **Флаг:** `FortID{...}` (замаскирован)
- **Бинарь:** `chall` (x86-64, PIE, full RELRO, NX) + исходник `chall.cpp`, приложенные `libc-2.39.so`, `libstdc++.so.6.0.33`
- **Описание (официальное):** сервис заметок `put idx val` / `get idx` с глобальным `std::string notes[8]` и БЕЗ проверки индекса

Сервис заметок, где каждая команда индексирует глобальный `std::string notes[8]` без единой проверки границ. `get` с отрицательным индексом читает память перед массивом как строку: слот `-1` - это структура locale/ctype, полная указателей, так что один `get -1` сливает и базу libstdc++, и базу libc (4096 байт). `put -1` пишет по существующему указателю этой «строки» (огромная ёмкость - assign копирует без переаллокации) прямо в ту же структуру. Внутри payload мы собираем поддельный setcontext-фрейм, перенаправляем указатель ctype-таблицы, который `istream::sentry` разыменует при следующем чтении, и превращаем классификацию символов в `execve("/bin/sh", ["/bin/sh", "-c", "cat flag.txt"])`.

Файлы:

- `solve.md` - полный разбор, включая тупики (английский)
- `solve.ru.md` - то же разбор на русском (рабочая копия)
- `scripts/solve.py` - эксплойт для remote (лик, payload, триггер; параметризован по версии)
