**Автор:** xer0 · **Категория:** rev / windows · **Баллы:** 50 · **Статус:** решено, полностью воспроизведено на оригинальном исполняемом файле.

> Our new license manager is unbreakable. Find a valid license key. (Tested under Wine & Windows.)

В архиве организаторов `virt.tar.gz` находится Windows x64-бинарник `virt.exe` с **виртуализированной самомодифицирующейся проверкой** в секции `.frost0`. Настоящий ключ имеет **40 символов**, а отдельно присутствует ложная ветка, выдающая 39-символьную строку `wrong{...}`.

## Решение найдено и проверено

Вместо полной деобфускации VM использован оригинальный вычислительный код:

- `vm_check(c,state,i)`, RVA `0x12340`: проверка одного символа.
- `vm_next(c,state,i)`, RVA `0x12410`: обновление состояния.
- Таблица ожидаемых значений, RVA `0x19860`, длина 40 байт.

C-программа [`solve_virt.c`](scripts/solve_virt.c) отображает PE в память Linux **по ImageBase `0x100000000`** и вызывает функции через `ms_abi`. По каждому индексу проверяет **95 печатных ASCII-символов** и получает единственное совпадение; затем обновляет состояние. Всего **3800 сравнений**, никакого перебора всех 40-символьных ключей.

Проверил **оригинальный `virt.exe`**: C-солвер собран с GCC, все 40 позиций восстановлены, конечное состояние `14792a50`, флаг совпадает с принятым на платформе.

```text
39  }  state=14792a50
FLAG: gctf{...}
final state: 14792a50
```

## Воспроизведение

В изолированной Linux x86-64 VM с GCC:

```sh
tar -xzf virt.tar.gz
gcc -O2 -Wall -Wextra -o solve_virt scripts/solve_virt.c
./solve_virt virt/virt.exe
```

**Важно:** C-программа выполняет машинные инструкции исходного PE внутри собственного процесса. Использовать отдельную CTF-VM, даже если точка входа Windows-программы не запускается.

Подробности в [solve.ru.md](solve.ru.md): ложный флаг, адреса RVA/VA, 413 самомодифицирующихся участков, вызовы VM, перенос секций PE в память и пошаговое извлечение ключа.
