# Stage 38A — однократное повторное открытие только агентского gate

Это не этап переключения плагина и не новая сессия PostgreSQL. Stage 38 уже создал ограниченный MCP permit; Stage 37A отозвал старый агентский gate через 20 минут. `seq=5` существует, отчёт отсутствует (`pre_journal`), повторной отправки задания не требуется.

## Входные ограничения

* Работает исключительно от непривилегированного пользователя `kali`.
* Проверяет действующий **существующий** `managed-mcp-write-permit35c.json`, точный task ID, `allow_create=false`, конфигурационный SHA и срок действия (не менее 180 секунд впереди).
* Проверяет 8 плагинов и точную конфигурацию восьмого, SHA кандидата, запущенный watchdog и его закреплённый исходник.
* Под тем же `flock` что у Stage 37A создаёт **только** `/home/kali/.config/bridge-pg-v2/managed-writes-stage34d-armed` с `O_EXCL`, `O_NOFOLLOW`, mode `0600`, fsync. Permit, PostgreSQL, конфиг, сервисы, сообщения и SDK не изменяет.
* Не продлевает permit. Gate автоматически удаляется watchdog через максимум 20 минут (плюс интервал таймера). При ошибке создавать gate вручную запрещено.
* Не запускать, если gate уже активен; это специально завершится STOP.

## Выполнение агентом

Скачать ZIP в `~/Downloads`, сверить SHA256 по хешу из поручения, распаковать приватно, проверить манифест, тесты и выполнить `510_arm_gate_only.sh` в **дочерней оболочке**, чтобы при STOP оболочка пользователя не закрылась. Возвратить все `STAGE38A_*` и `rc`.

После маркера `STAGE38A_NOW_AGENT_CAN_RESUME_EXACT_EXISTING_REPORT_SEQ5`:

1. Через штатный managed Inbox / CLI проверить `status` по `message_id=pgv2-mg-b6c26aa18220412bafdbf32393f16568-5-report`.
2. Если запись отсутствует и нет неопределённого исхода, отправить только ранее подтверждённую диагностику порта 8789 тем же `message_id` и с текущей версией диалога; не отправлять заново `seq=5`.
3. Проверить статус; вернуть `seq`, `message_id` и состояние gate. Не создавать новую задачу, не выполнять HTTP POST к Taskboard, не выводить секреты.
4. Когда ChatGPT проверит и ACK отчёт `seq=6`, отдельно отозвать gate и permit через Stage 37A.

## Если permit истёк

`STAGE38A_STOP_PERMIT_EXPIRED_OR_TOO_CLOSE`: ничего не изменится. Потребуется **новое явно разрешённое операционное окно** с новым permit, этот скрипт его не создаст.

## Дополнительное ограничение

Gate Stage 34D является локальным флагом разрешения записи для агентского CLI; **сам по себе он не привязан криптографически к одному task_id**. Изоляция достигается также конфигурацией восьмого плагина и временным окном. Это не повод использовать gate для иных задач.
