# Stage 37: план эксплуатационной готовности моста

**Исходное состояние:** Stage 36 завершён, оба сообщения (`seq=1 task`, `seq=2 report`) доставлены по одной попытке, отчёт подтверждён ACK, dispatch=false; в MultiTool восемь плагинов; агентский CLI gate и MCP write permit отозваны. Доступ к БД по `bridge_chatgpt` в режиме read-only работает.

| Этап | Реализация | Приёмочные критерии | Особые ограничения |
|---|---|---|---|
| **37A** | Ревокер разрешений, независимый от SHA `opencode.json`; карантин вместо уничтожения, безопасная идемпотентность, watchdog просрочки и некорректных разрешений | Повторный вызов безопасен; `status` показывает 0 активных разрешений; изменённый конфиг не мешает отзыву; watchdog/timer active | Не выдавать разрешения и не изменять БД |
| **37B** | Проверка перезапуска MultiTool, восстановление из durable state, обработка orphaned lease | Сообщения не теряются и отчёт не дублируется; каждый side effect с детерминированным ID | Отдельный тестовый dialogue и ограниченный permit |
| **37C** | Контроль очереди: lease TTL, retry policy, duplicate detection, отчёты и квитанции | Failure injection: kill/restart, истечение lease, повторный tick; не более одного логического отчёта, durable receipt | Не затрагивать старую канарейку |
| **37D** | Регистрация managed Inbox для новых диалогов через контролируемый registry/one-plugin dispatcher, не ручной append plugin на каждый task | Подключение/отключение task без перезаписи `opencode.json`, scope по task_id, без расширения полномочий CLI | Убрать OS-user-wide gate или изолировать сервис |
| **37E** | Сквозная приёмка: авторизация MCP, безопасность permit, рестарт, очередь, rollback, приёмка логов и статистики | Независимый аудит, воспроизводимые тесты и документированное восстановление | Только после 37B–37D |

**Зависимости:** 37A не открывает запись. Для следующего теста нужен отдельный ревизованный grant/lease mechanism, согласованный с watcher. После 37B нужна изоляция агентского CLI: текущий файл-gate позволяет любому процессу с тем же UID `kali` выполнить роль агента, поэтому он не является достаточным производственным контролем доступа. Этот риск отдельно оценивается на 37D/37E.
