DEStruction — решение двух флагов

Файлы:
- destruction_solve.py: быстрый гарантированный вариант для FLAG0. Одно шифрование, максимум две проверки.
- destruction_full_solve.py: получение FLAG0 и FLAG1. Одно шифрование с 1 MiB AD, до 96 проверок тега, восстановление H и два запроса для FLAG1. Работает на стандартной библиотеке Python 3.

Пример запуска:
    python3 destruction_full_solve.py HOST PORT

Результат: вывод FLAG0, H (8 байт hex), FLAG1.

Техническая суть:
Шифр 3DES используется с самодельным GCM на 64-битных блоках. Тег обрезан до 2 байт. Запрос encryption может дать около 1 MiB AD, а submit принимает произвольные AD.

Если исходный plaintext выбран равным ASCII "ABCDEFGHflag", меняем шифртекст первой группы из 8 байт так, чтобы после расшифрования получилась строка "give me flag". При том же IV keystream не меняется. Одновременно меняем 15 блоков AD с позициями, соответствующими степеням H^(2^j), где j=3..17. Их коэффициенты решаются по линейной системе над GF(2): для любого H первые 15 бит GHASH-разности равны нулю. Один оставшийся бит требует перебора двух тегов => FLAG0.

Для FLAG1 аналогичная система с 14 фиксированными нулевыми битами дает семейство допустимых AD. В заранее выбранных 32 линейно независимых вариантах два последних бита тега кодируют 64 независимых бинарных уравнения от H. Каждый вариант требует не более трех проверок тегов (0, 1, 2; при трех отказах вариант 3 однозначно определён). Решаем систему 64x64 и получаем все 8 байт H. Затем запрос encryption на plaintext H + "zzzz" и отправка того же шифртекста в submit возвращает FLAG1.

Проверки:
- Оба метода проверены на оригинальной функции GHASH из encryption.py.
- FLAG0 проверен сквозным тестом с локальным эмулятором сервера.
- Восстановление H и обе ветки флагов проверены сквозным протокольным тестом с локальным эмулятором.
- Реальный challenge-хост не предоставлен, поэтому значения настоящих флагов не получены.
