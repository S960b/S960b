# Fish Pond (fishies) - черновик решения

Платформа: Platypwn 2026, категория web. Инстанс: `http://<host>/`.
Флаг: `PP{MASK}` (полное значение не хранится в репозитории, см.
`/home/kali/ctf-archive/fishies/FLAG.txt`), получен.

## Условие

Страница с рыбами: можно добавить свою рыбу (`POST /api/fish`, поля `ascii` и
`fishData`), у каждой рыбы есть кнопка report (`POST /api/fish/:id/report`).
Репорт запускает headless-бота с админской cookie на `/#fishN`. Есть админский
PATCH `fishData` и админский debug-fetch по loopback. Флаг лежит в `/flag.txt`
внутри контейнера и по HTTP не отдаётся.

## Что даёт вход

1. Баг в `escape()` (`server.js`): после замены `>` на `&gt;` цикл делает
   `index += replacement.length` и пропускает следующий символ. Поэтому `<`,
   стоящий сразу после `>`, остаётся литеральным.
   Значение `ascii` вида `><img src=x onerror="...">` рендерится в `<pre>` как
   настоящий `<img>`. Проверка: `GET /` содержит `&gt;<img src=x onerror=...`.
2. Бот приходит с админской cookie, поэтому XSS работает в админском контексте.
3. `combine()` в `PATCH /api/admin/fish/:id/fishData` рекурсивно мержит тело в
   `fish.fishData`. Ключ `__proto__` из JSON.parse становится собственным
   свойством и уводит рекурсию в `Object.prototype` (prototype pollution).
4. `puppeteer.launch()` в `visitFish` не задаёт собственные `downloadBehavior` и
   `env`, поэтому загрязнённые значения наследуются через прототип:
   - `downloadBehavior = {policy: 'allow', downloadPath: '<dir>'}` уводит
     скачивание Chromium в нужный каталог (каталог создаётся автоматически);
   - `env.LD_PRELOAD` подсовывает свой `.so` следующему процессу Chromium.

## Цепочка

1. Создать рыбу с ascii `><img src=x onerror="...">`, где обработчик делает
   `PATCH` с телом `{"__proto__":{"downloadBehavior":{...},"env":{...}}}`.
2. Report этой рыбы: pollution применится к следующему запуску браузера.
3. Report повторно: у бота уже активен `downloadBehavior`, и его XSS-страница
   скачивает `payload.so` с нашего HTTP-сервера прямо в каталог, который
   раздаёт express (`/app/static/<dir>`). Проверка успеха:
   `GET /static/<dir>/payload.so` возвращает 200 и точный размер файла.
4. Вторая рыба с ascii, который делает `PATCH` с
   `{"__proto__":{"env":{"LD_PRELOAD":"<dir>/payload.so"}}}`.
5. Report второй рыбы: ставит `LD_PRELOAD` для следующего запуска.
6. Report ещё раз: новый Chromium загружает `.so`, конструктор читает
   `/flag.txt` и отправляет его POST-запросом на наш листенер. Копия файла
   дополнительно кладётся в раздаваемый каталог: `GET /static/<dir>/flag.txt`.

Итог: `PP{MASK}`.

## Грабли

- Загрязнение действует только на СЛЕДУЮЩИЙ запуск браузера: после PATCH нужен
  ещё один report, иначе эффекта не видно.
- `env` полностью заменяет `process.env` дочернего процесса, поэтому `PATH`
  нужно передавать явно.
- Двойные кавычки внутри `onerror` надо отдавать как `&quot;`, иначе
  HTML-парсер обрывает атрибут на первой кавычке и XSS не срабатывает.
- Собирать JSON с `__proto__` в JS нельзя литералом: `{__proto__: {...}}`
  задаёт прототип и `JSON.stringify` его выбрасывает. Нужен
  `JSON.stringify(JSON.parse('{"__proto__":...}'))` или готовая строка.
- Имя скачанного файла при `policy: 'allow'` равно basename из URL (атрибут
  `download` для cross-origin игнорируется), поэтому путь для `LD_PRELOAD`
  предсказуем.
- Скачивание в headless работает без user gesture.
