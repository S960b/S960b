# Frostgate License Manager — виртуализированная проверка лицензии

[English version](solve.md)

## Задание и бинарник

Нужно найти лицензию, которую принимает Windows-программа `virt.exe`. Оригинальный архив `virt.tar.gz` содержит только `virt/virt.exe` размером **154 624 байта** и `virt/sha256sum`. Проверка `sha256sum -c` успешно пройдена.

Статический анализ показал PE32+ / x86-64 (Delphi), точку входа RVA `0x16a0`, базу `0x100000000` и восемь секций, включая специальную `.frost0` по смещению файла `0x22200`, размером `0x38e4`. При просмотре строк видны:

```text
Frostgate License Manager  v3.1
Enter license key:
Checking license, please wait...
```

Приложение рассчитано на Wine и Windows, а проверка лицензии реализована через **виртуализированные функции**.

## Реальный результат из старого диалога

Из разговора о решении от **20 ноября 2026 года** удалось восстановить:

1. Правильная лицензия имеет **ровно 40 символов**, начинается с `gctf{` и заканчивается `}`.
2. В бинарнике есть виртуализированная логика проверки, а не обычное сравнение с текстовой константой.
3. При исследовании для **каждой позиции** был определён **ровно один подходящий печатный символ**.
4. Отдельная ложная ветка расшифровывала `wrong{f1n4l1z3r_d3c0y_n0t_th3_r34l_0n3}` — это **приманка**, а не найденный флаг.
5. Найденный 40-символьный ключ принят платформой согласно подтверждению участника.

В публичном GitHub флаг скрыт, как и в других write-up серии.

## Почему нельзя использовать строку wrong{...}

Наличие в бинарнике структуры, похожей на флаг, ничего не доказывает. Здесь ложный результат явно обозначает **decoy**, поэтому извлечения первой читаемой строки недостаточно. Нужно учитывать, по какому пути идёт реальная проверка лицензии, и подтверждать выполнение условия приёма.

Историческое исследование использовало проверку кандидатов по позициям через виртуализированный алгоритм. В этом сеансе запуск под Wine/Windows **не выполнялся** — таких инструментов в текущей среде нет. Не следует выдавать старый успешный результат за новый прогон.

## Сохранившиеся и недостающие данные

В архиве есть оригинальный PE и список хешей. Скрипт [inspect_handout.py](scripts/inspect_handout.py) проверяет бинарник и структуру секций **без запуска программы**.

В прошлых сообщениях сохранился сам найденный и принятый ключ, но не сохранились **полная трасса VM и исходный переборщик**, а архив организаторов их и не содержит. Поэтому конкретные VM-опкоды, точные offsets всех проверок и выдуманный «готовый solver» не публикуются.

## Вывод

Защита через виртуализацию и ложные расшифровываемые строки затрудняет анализ, но не гарантирует стойкость. Для качественного райтапа важно отделять **приманку**, **исторический ключ, реально принятый платформой**, и те внутренние детали, для которых уже нет сохранившихся доказательств.
