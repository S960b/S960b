# MeowSim: флаг за невозможным состоянием

[English](solve.md)

## 0. План

Приложение это карманная лаборатория с квантовым котом: кормить, гладить, лечить, наблюдать. Вопрос в том, даёт ли флаг долгая игра или выполнение условия в коде. Статический разбор отвечает на это быстрее кликов.

Инструменты: APK это ZIP, поэтому сначала `unzip -l`, затем дизассемблер DEX. JADX на машине не было, поэтому DEX читался библиотекой для Python и дизассемблировался по методам (`androguard`).

Зачем этот шаг: вся задача это булево условие плюс процедура расшифровки, и обе читаются без запуска Android.

## 1. Условие

`QuantumState.canOpenFlagVault()` требует шесть условий сразу:

```text
pet.catAlive        == true
box.catDead         == true
box.superposition   == true
box.stability       >= 90
observer.observed   == false
tampered            == false
```

Первые два в обычной игре противоречат друг другу, и в этом весь смысл. `observed` должен остаться false, поэтому очевидный ход, заглянуть в коробку, это ловушка.

Зачем этот шаг: это и есть условие приёма, всё дальнейшее это разбор того, как хранится состояние.

## 2. Где лежит состояние

Четыре хранилища, все видны в DEX:

- `PetStore`, SharedPreferences `pet_state`: `catAlive`, голод, настроение, энергия, здоровье, чистота.
- `BoxStore`, SQLite `box_state.db`, таблица `box_state`: `boxClosed`, `catDead`, `superposition`, `stability`, `boxSeal`.
- `ObserverStore`, SharedPreferences `observer_state`: `observed`, `observerToken`, `lastMeasurement`. Токен по умолчанию это литерал `ny4n-lab-token`.
- `StateRepository` связывает их в `QuantumState` и содержит действия.

Две детали важны дальше. `stabilize()` записывает `stability = 92`, то есть 92 это не выдумка решающего, а значение, которое ставит само приложение. И `BoxStore.sealFor()` считает печать как

```text
sha256_hex("box|" + catDead + "|" + superposition + "|" + stability + "|meowsim-v1")
```

то есть печать связывает именно те поля коробки, от которых зависит ключ флага.

## 3. Как достижимо невозможное состояние

`RestoreExperimentActivity` это лабораторная функция: она принимает intent с `mode`, `snapshot` и `seal`, проверяет печать через `SealVerifier` (`sha256(observer | box | "restore-v1")`) и восстанавливает коробку из снимка. Снимок это небольшой текст из пар `key=value`, который разбирает `ExperimentSnapshot.parse`: `catAlive`, `catDead`, `superposition`, `observed`, `restoreObserverState`, `stability`.

Ошибка в самом слове «восстановить»: коробка восстанавливается из снимка, а запись наблюдателя восстанавливается отдельно, а то и вовсе нет. Это расцепление и позволяет одновременно иметь `catAlive` в записи питомца и `catDead` в записи коробки, сохранив `observed=false`. `TamperDetector` проверяет только имя пакета, поэтому переподпись APK ничего не даёт и не нужна: путь восстановления это штатная функция приложения.

Зачем этот шаг: без пути восстановления шесть условий взаимно исключают друг друга, с ним всё сводится к тому, в какое хранилище писать.

## 4. Флаг зашифрован, а не сохранён

`FlagVault` держит массив из 23 байт (`ENCRYPTED_FLAG`) и выводит ключ из состояния:

```text
key = sha256(observerToken | boxSeal | stability | catAlive | catDead |
             superposition | observed | "meowsim-v1")
```

Ключевой поток это конкатенация блоков `sha256(key || be32(counter))`, обрезанная до 23 байт, а открытый текст это XOR массива с этим потоком. Результат принимается только если начинается с `ctfcup{`.

То есть `strings` флаг не даст: его надо собрать при правильных значениях состояния, порядке байт и выводе ключа. `scripts/decrypt_flag.py` делает ровно это со значениями по умолчанию: токен `ny4n-lab-token`, `observed=false`, кот жив и мёртв, суперпозиция включена, стабильность 92.

Зачем этот шаг: сам зашифрованный массив бесполезен, а состояние без него не даёт текста; решение это они вместе.

## 5. Результат

С состоянием выше расшифровка возвращает 23 читаемых байта нужного формата, задача была сдана. Флаг здесь скрыт как `ctfcup{...}`.

```bash
python3 scripts/decrypt_flag.py                 # состояние по умолчанию, стабильность 92
python3 scripts/decrypt_flag.py --observed      # контроль: отказ
```

Второй запуск падает намеренно: это показывает, что `observed=true` отсекается условием, а не даёт молча мусор, похожий на флаг.

## 6. Выводы

- Отделять игровую логику от условия безопасности: сюжет предлагает наблюдать, код это запрещает.
- Искать в приложении функции восстановления и импорта: они часто расцепляют поля, которые обычный поток держит согласованными.
- Если флаг шифруется ключом из состояния, в райтапе нужен точный порядок конкатенации и точный формат байт, иначе он невоспроизводим.

Одним абзацем: хранилище флага открывается только в состоянии, где питомец жив, коробка сообщает о смерти и суперпозиции, стабильность не меньше 90, а наблюдатель ничего не измерял; лабораторное восстановление позволяет вернуть коробку из снимка независимо от наблюдателя, `stabilize()` даёт стабильность 92, и 23 зашифрованных байта расшифровываются ключом SHA-256 по этому состоянию и XOR-потоком из хешей счётчика.
