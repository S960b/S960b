# FSenc: the ChaCha20-Poly1305 key was inside the file

[По-русски](solve.ru.md)

## 1. Understanding the file format

FSenc uses Argon2id for deriving encryption material and ChaCha20-Poly1305 for file encryption. The investigation of the binary and a known-password sample established the serialized format:

```text
bytes  0..11  : 12-byte magic
bytes 12..43  : 32-byte ChaCha20-Poly1305 key
bytes 44..55  : 12-byte nonce
bytes 56..end : ciphertext followed by its 16-byte authentication tag
```

The 44 bytes at offsets `12:56` were generated by the password KDF but then stored **unprotected in the encrypted file itself**. Consequently, once the file is available, recovering or guessing its password is unnecessary.

## 2. Reverse-engineering the key derivation

A fixed password produced the same 44-byte field for different input files. Debugger observations at `argon2::Argon2::hash_password_into` and a local comparison identified the derivation as:

```text
Argon2id(password, salt=magic || magic[:4],
         time_cost=2, memory_cost=19456 KiB,
         parallelism=1, output_len=44)
```

This explains the deterministic header. Early dictionary and known-password tests were useful experiments, but the decisive realization was that the first 32 header bytes are already the key and the remaining 12 are the nonce.

## 3. The working decryption

The saved competition command ran:

```python
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

data = open("flag.bin", "rb").read()
header = data[12:56]
key, nonce = header[:32], header[32:44]
plaintext = ChaCha20Poly1305(key).decrypt(nonce, data[56:], None)
print("PLAINTEXT:", plaintext)
```

Its actual result:

```text
key   aa1ac2b4ea02d933d65a9c20d8a116f00e3d1094d03cd9d19cb75a9da4b399dd
nonce 8d3b427242a42d5c0df5e60f
PLAINTEXT: b'PP{f1l3_3ncrypt10n_…sUfPL}\n'
```

The flag was **accepted by the platform**. The source-derived reproduction script in the repository provides this operation using:

```bash
python3 scripts/inspect_fsenc.py flag.bin --direct
```

The diagnostic script also has Argon2id/password modes, but the accepted solution used direct-header decryption.

## 4. Root cause and lesson

ChaCha20-Poly1305 can be implemented correctly yet provide no secrecy if the corresponding encryption key is written alongside the ciphertext. A safe password-based format may publish an independent salt and a nonce, but must keep the derived key secret and rederive it from the password on decryption. Nonce uniqueness and header authentication must also be enforced.
