# My Own FS: восстановление удалённого файла из самодельной ФС

[English](solve.md)

## 0. Что в архиве

`my-own-fs.zip` содержит файловую систему на Rust (FUSE), её исходник и собранный из неё `disk.img` на 4 МиБ. Задача это файловая система: найти на диске флаг.

Исходник и есть спецификация, поэтому первый шаг это прочитать раскладку, а не угадывать по hexdump.

## 1. Раскладка

Из шапки `main.rs`, где `N = размер_образа / 1338`:

```text
[0, N)                          таблица инодов, по байту на инод: 0 свободен, 1 занят
[N + i*1337, N + (i+1)*1337)    инод i, 1337 байт
```

Инод начинается с 32-битного little-endian указателя `next` и байта типа. Головной инод (тип 1 файл, тип 2 каталог) несёт 51-байтовую шапку:

```text
0  u32 next    4  u8 type     5  u16 mode    7  u32 uid   11  u32 gid
15 u64 size    23 i64 atime   31 i64 mtime   39 i64 ctime 47 u32 nlink
51 ... данные
```

У инода-продолжения шапка всего 5 байт (`next`, тип 0), дальше данные. Данные каталога это последовательность записей: `u32 inode`, `u8 name_len`, имя.

Зачем этот шаг: всё остальное выводится из этих смещений, а ошибка в размере шапки сдвигает каждое чтение на 46 байт.

## 2. Что прячет инструментарий

У `myfs` есть подкоманда `shuffle`, которая переставляет слоты инодов. Она меняет только физические позиции: цепочки и данные внутри инодов не трогаются, поэтому обход по цепочкам работает и после перемешивания.

`unlink` помечает байт в таблице инодов как свободный и убирает запись из каталога, но данные инода не затирает. В этом и уязвимость: удалённые файлы остаются читаемыми на диске.

Зачем этот шаг: понимание, что удаление меняет только метаданные, превращает задачу в карвинг, а не в восстановление журнала ФС.

## 3. Обход цепочек

Живое дерево это приманка: `/README.txt` говорит «nothing to see here, everything was cleaned up», а `/todo.txt` это список покупок. Чтение смонтированной ФС ничего не даёт.

Полезный ход это игнорировать дерево каталогов и обойти все иноды таблицы:

1. Для `i` от `0` до `N` прочитать 51-байтовую шапку по смещению `N + i*1337`.
2. Пропустить иноды, у которых тип не 1 и не 2.
3. Идти по `next`, пока он не ноль и не встречался, склеивая данные шапки и данные каждого продолжения.
4. Обрезать по записанному `size`.
5. Проверить первые байты на известную сигнатуру.

Зачем этот шаг: у освобождённых инодов сохраняются тип и размер, поэтому цепочка остаётся проходимой после удаления, и из каталога ничего разбирать не нужно.

## 4. Где флаг

Скан возвращает ровно один файл, чьи данные начинаются с `\x89PNG\r\n\x1a\n`: инод 2979, цепочка из 161 инода, 214 153 байта, изображение 900 на 160 в RGB. В картинке текст флага, поэтому последний шаг это посмотреть на неё.

```bash
python3 scripts/carve_png.py disk.img carved.png
```

Вырезанный файл побайтово совпадает с изображением, которое достаётся через удалённый инод, и это проверка корректности обхода: неверная граница цепочки даёт обрезанный или дополненный PNG, который не декодируется.

Флаг в репозитории скрыт как `ctfcup{...}`.

Зачем этот шаг: PNG лежит не в слак-пространстве и не в неразмеченных блоках, а обычным файлом в освобождённых инодах. Недоступен он через монтирование только потому, что удалена запись каталога.

## 5. Тупики

- Смонтировать образ и ходить по дереву: дерево намеренно не содержит полезных файлов.
- `strings` по сырому образу: данные PNG сжаты, текстовый поиск ничего не находит.
- Считать важным seed перемешивания: он переставляет слоты, а не данные, обходу цепочек это безразлично.

## 6. Выводы

- Для самодельной ФС сначала читать комментарий с раскладкой; смещения и есть вся задача.
- Удаление обычно убирает имена, а не байты: сканировать таблицу инодов, а не дерево каталогов.
- Корректность карвинга проверять декодированием результата, а не размером.

Одним абзацем: образ хранит таблицу по байту на инод и иноды по 1337 байт, связанные указателем `next`; удаление только сбрасывает бит занятости и убирает запись каталога, поэтому обход всех инодов с проходом по цепочкам восстанавливает удалённый PNG на 214 КБ в иноде 2979, а флаг написан внутри этой картинки.
