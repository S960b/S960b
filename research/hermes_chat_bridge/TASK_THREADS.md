# Один чат — одна задача

Постоянный `task_id` обозначает беседу. `title` — её тема, не имя очереди.
На табло одна строка на `task_id`: направление последней передачи,
два независимых индикатора ChatGPT / MT, история с полными текстами.

Для каждого нового сообщения остаётся внутренний `job_id` (turn ID).
Это необходимо для старых webhook, claim/lease, идемпотентности и защиты
от запоздавшего ответа на предыдущий ход. Эти ID не создают отдельные
строки на новом табло. Ответ на ход не означает закрытия всей беседы.

## Как продолжать

- Первая отправка: `bridge_put_message(text=..., title="Доработка моста", idempotency_key=...)`.
  Сохранить возвращённый `task_id` в контексте чата.
- Все последующие отправки: тот же инструмент с `task_id=...` и новым ключом.
  Повтор потерянного запроса — с прежним ключом и текстом.
- `bridge_get_message` возвращает `task_id`. `bridge_put_reply` отвечает
  на конкретный `job_id` из события, как прежде, с тем же consumer_id.
- Локально: `bridge-cli task "Тема" "Первое сообщение"`, затем
  `bridge-cli send task_... "Следующий отчёт" уникальный_ключ`.
- Worker сохраняет `task_id` в state, включая восстановление из старого
  `current_job_id`. Его следующие отчёты остаются в этой беседе.
- `complete_to_hermes` привязывает обратный отчёт к тому же `task_id`.

MCP не предоставляет серверу достоверный ID текущего ChatGPT-чата.
Поэтому связывание явно через `task_id`, а не угадыванием по тексту,
владельцу или `queue=test`. Без `task_id` старый API намеренно создаёт
новую беседу. Агентам нельзя использовать его без ID для продолжения.
До обновления клиентов старые отправители всё ещё могут плодить беседы;
новый интерфейс не выдаёт их за один чат искусственно.

## Состояния и защита

- Жёлтый «ожидает получения»: отправлено, но claim ещё не получен.
- Жёлтый «в работе»: живой claim. Это подтверждение получения, а не
  доказательство работы модели; lease/heartbeat отражает активность.
- Зелёный «ответил» или «передал данные»: соответствующее действие записано.
- Красный «ошибка»: failed. Красный «нет активности 10 минут»: 600 секунд
  без обновления ожидающего хода. Тайм-аут не запускает автоматический retry.
- Серый: активного поручения нет. Обычный ответ не создаёт новый запуск MT.
- Атомарный `task_busy` не допускает второго pending-хода при явном
  продолжении одной беседы, в том числе из двух конкурентных соединений.
- Предыдущее сообщение, ответ и направление не перезаписываются.

## Миграция и установка

Миграция добавляет `jobs.task_id` и `bridge_tasks`, не удаляет сообщения.
Старые строки объединяются ТОЛЬКО по существующим `parent_job_id`.
Несвязанные ежедневные дубликаты не объединяются автоматически: нет
достоверного соответствия ChatGPT-чату.

Перед установкой сделать согласованный SQLite backup рабочей базы.
Применить изменения репозитория к серверу и taskboard вместе, используя
существующую конфигурацию сервисов; не менять OAuth, URL туннеля и подписки.
`BRIDGE_DB_PATH` у обоих процессов должен указывать на одну базу.
Запуск нового сервера или taskboard выполняет идемпотентную миграцию.
После рестарта обновить схему MCP-коннектора: у `bridge_put_message`
должны появиться `task_id` и `title`. Обновить локальные отправители/инструкции
на `send` / явный `task_id`; иначе старый `put` продолжит создавать новые беседы.

Проверка: обмен MT → ChatGPT → MT → ChatGPT должен остаться одной строкой,
история растёт, ID неизменен, конкурентный send возвращает `task_busy`.
Старые `/api/jobs` и `/api/action` оставлены для совместимости;
новое табло читает `/api/tasks` и не предлагает необратимое удаление истории.

Проверено локально на временных БД: 7 новых тестов пройдены; полный набор
121 passed, 4 failed, 3 xfailed. Все 4 падения воспроизведены также на
неизменённом HEAD (114 passed, 4 failed, 3 xfailed): три старых теста native
subscribe и старый тест лимита 8KiB против текущего MAX_TEXT_BYTES=30720.
Рабочая база и сервис localhost:8787 на машине владельца здесь не проверены.
Браузерная визуальная проверка заблокирована отсутствием Chromium и ошибкой
скачивания его архива; успешный browser E2E не заявляется.
