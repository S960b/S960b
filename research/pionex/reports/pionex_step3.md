# Pionex — шаг 3: margin-survivability + cost audit

Без ордеров, без нового длительного сбора: 8H-траектории (500 funding
периодов) + официальные документы. Ключ не использовался в расчётах.

## 1. Официальные параметры контрактов (публичный /api/v1/common/symbols)

- AAVE_USDT_PERP: baseStep 0.01, size=базовый актив, liquidationFeeRate 0.014.
- ARKM_USDT_PERP: baseStep 1, liquidationFeeRate 0.022.
- AMZNX_USDT_PERP / AAPLX_USDT_PERP: baseStep 0.01, liquidationFeeRate 0.015.
- Множитель контракта = 1 (USDT-margined, size в базовом активе).
- Формула (блог Pionex, проверено 2026-10-06): Maintenance Margin =
  Position Notional(V) × MMR − Margin Amount, tiered; BTC tier1: 0.50%,
  0–150k USDT. Для наших контрактов отдельных tier-таблиц публично нет —
  MMR берётся стрессом 0.5%/1%/2% с опорой на официальную формулу.

## 2. Модель margin-survivability (по замечаниям ревизии)

Позиция: long spot + short perp, единый масштаб spot-покупка = 200 USDT
(q = 200/S0), постоянный q. Futures equity на каждом периоде:
  E_t = C_fut + funding_to_t + q·(F_0 − F_t) − fee_fut_in
  ликвидация если E_t < MM_t = |q|·F_t·MMR.
Ищем минимальный C_fut без ликвидации за всё окно; cfut_deployed = C_fut×1.2
(запас 20%). C_deployed = spot_cost + cfut_deployed.
Сценарий A (isolated, без auto-transfer): потеря short-ноги не компенсируется
spot-прибылью автоматически — именно поэтому резерв обязателен.
Cross/unified НЕ предполагался (документального подтверждения, что spot/USDT
признаются collateral фьючерсной позиции, не найдено — пометил как НЕ
доказано; если это не так, доходность ещё ниже).

## 6. xStocks (AMZNX, AAPLX) — исключены из подтверждаемой доходности

- Официальный FAQ (блог xStocks, проверено 2026-09-04, fsses подтверждены
  февраль-сентябрь 2026): spot fill 0.1% (10 bps), futures 0.02% maker /
  0.05% taker, funding отдельно.
- Position rewards: с 2026-09-03 16:00 UTC spot получает USDT-награду
  (Position Rewards), futures — отдельная Profit Distribution (Corporate
  Dividend): long получает, short платит. Публичный fundingRate может НЕ
  включать её. В нашем окне (2026-04-22 → 2026-10-06) период после
  2026-09-03 присутствует (33 дня), но по обеим сторонам adjustment
  публичных данных нет.
- ВЫВОД: для AMZNX/AAPLX подтвердить доходность нельзя, пока не известны
  размер и сторона corporate adjustment. Оставить research-only. TC (short)
  мог нести неучтённые выплаты, уменьшающие/убивающие carry. В отчётах
  вопроса больше не поднимаю до появления данных.

## 7. Неизвестные / ограничения
- MMR tier для конкретных контрактов публично не опубликован — стресс
  0.5/1/2%, источнник — официальная формула + BTC пример.
- Режим маржи isolated/cross и documental cross-collateral — не подтверждён;
  считали по сценарию A (isolated), он консервативнее.
- Фактический fee-тариф владельца не подтверждён (fills пусты) — применяли
  официальные публичные ставки.
- Slippage и глубины (top-1/top-5 при $100/500/1000) — не измерены, нужен
  WS-пилот.
- 0.5% fundingRate как «доля» — подтверждено блогами (Position Value × Rate,
  positive => long→short); соответствие поля API fundingRate этой ставке
  проверить на реальном филле невозможно (нет сделок).

## 8. Итог по funding carry (честный)
- С margin-аудитом и неперекрывающимися окнами картина слабее, чем в 2б:
  AAVE ~94 bps за 166 дн на C_deployed (~2.1%/год условно), 30d-окна не все
  положительны (4/5). ARKM ~147 bps (~3.2%/год), тоже 4/5 по 30d.
- xStocks исключены. Долгий carry (≥60d) выглядит стабильнее коротких окон,
  но 166 дней — единственный исторический отрезок.
- Это по-прежнему НЕ подтверждение доходности: требуются p50/p90 спредов,
  volume top-N, staleness (WS 24ч на AAVE/ARKM), и отдельное решение по
  сценарию cross-margin.
