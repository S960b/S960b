# Stage 38 — операционное окно для уже проверенного диалога

Цель: сделать уже работающий ChatGPT pg ↔ PostgreSQL ↔ MultiTool пригодным для одной реальной задачи **до** дополнительного аудита восстановления. Используется существующий диалог `task_b6c26aa18220412bafdbf32393f16568`, созданный и прошедший полный E2E в Stage 36, и установленный восьмой плагин 37B2C. Не регистрируются новые плагины и диалоги, не перезапускаются службы.

1. Запустить `500_arm_one_dialogue.sh` из распакованного архива. Подтвердить маркер `STAGE38_NEXT_CHATGPT_ENABLE_DISPATCH_AND_SEND_ONE_TASK`. Не повторять при STOP.
2. ChatGPT через pg независимо проверяет `managed_health` (`write_permit_present=true`) и `managed_status` существующего диалога (`dispatch=false`, version=2, policy_version=2), затем включает dispatch, отправляет **одно** явно сформулированное поручение пользователя с уникальным стабильным `message_id` и корректным `expected_version`.
3. Agent/MultiTool получает это поручение штатно в уже зарегистрированном восьмом плагине. ChatGPT проверяет отчёт, выполняет ACK, отключает dispatch и вызывает `501_emergency_revoke.sh` через агента.
4. По истечении 20 минут запись отчётов агентом автоматически закрывает Stage37A watchdog независимо от состояния задания. MCP permit автоматически истекает через 60 минут. Для длинных задач **нужно заранее согласовать продление gate с явным новым разрешением оператора**, иначе отчёт может быть заблокирован после 20 минут. Самостоятельно продлевать gate агенту нельзя.
5. При любой ошибке закрыть обе привилегии `501_emergency_revoke.sh` (не зависит от SHA конфига). После закрытия оператор проверяет `pg managed_health write_permit_present=false`, `dispatch_enabled=false`, либо безопасно отключает dispatch через действующее ограниченное разрешение до отзыва.

Защита: фиксированный SHA `f46c3d4c2a46…` (8 плагинов), только разрешённый task_id, `allow_create=false`, активный 37A watchdog, пустой inflight и журнал неопределённых claim, доступные MCP /ping и tunnel /readyz. Не меняет PostgreSQL, код, конфиг, службы; создаёт только два временных capability-файла. Возврат к временно закрытому состоянию — штатный независимый 37A revoke.

Нерешённый риск: crash между SQL claim и локальным inflight: кандидат 37B2C предотвращает повторный SDK-запуск, но может оставить задачу на ручное восстановление. Не используйте окно для необратимых задач без отдельного согласования и внешней идемпотентности.
