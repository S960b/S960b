# Контракт стороны публичного потока SafeTrade (этап, ~1ч)

Дата: 2026-10-04. Ограниченный этап по ревью 6d01aae: установить, что кодирует
публичное поле `side` и есть ли `taker_type`. Без торговых проб, без новых
сделок, ключ не использовался для создания/изменения чего-либо.

## Вопросы и ответы

### 1. Есть ли taker_type?

**Нет — ни в публичном, ни в приватном потоке SafeTrade.**

- Публичный `GET /api/v2/trade/public/markets/{market}/trades` (свежий ответ,
  PRL): поля `id, market, price, amount, total, side, created_at`. taker_type
  отсутствует.
- Приватный `GET /api/v2/trade/market/trades` (свои исполнения, read-only):
  поля `id, market, order_id, order_side, side, price, amount, total, fee,
  fee_currency, created_at`. taker_type отсутствует.
- В каноническом Peatio/OpenWare (2-6-stable, исходники
  app/api/v2/entities/public_trade.rb) публичный trade отдаёт ИМЕННО
  `taker_type` — «Trade taker order type (sell or buy)». Поле `side` там
  отсутствует. Значит сборка SafeTrade кастомизирована: taker_type заменён
  на `side` (или добавлен side с той же семантикой). Каноническая документация
  применима только с оговоркой.

### 2. Что кодирует публичное side?

**Косвенно — сторону агрессора (taker), с высокой согласованностью; прямой
документальный контракт сборки не найден.**

Косвенная диагностика на замороженном снимке frozen run (mk_18db19212772b000,
cutoff 2026-10-04T16:15:37Z; JSON-отчёт
reports/side_semantics_mk_18db19212772b000_cutoff_20261004T161537Z.json, rc=0;
входы depth/trades со SHA256 1e7f6daf…c31b9 / c71ef6e1…899cb). Гипотеза:
цена≈ask → buy, цена≈bid → sell значит side=агрессор; обратное соответствие =
side=пассивная сторона.

Методика (BBO-only, дедуп по (pair,id)):
- В расчёт берётся только BBO снимка: best_bid=max(bids), best_ask=min(asks);
  глубокие уровни — не граница спреда и не учитываются.
- Сделка classified, если её цена совпала с best_bid или best_ask в пределах
  tick (PRL 0.01 / QUANTUS 0.001 / LTC 0.00001); равенство расстояний до BBO
  (середина) → ambiguous; нет валидного снимка ≤30с → no_snap; иначе (внутри
  спреда/сдвиг) → indet.
- Дедупликация по (pair,id): повторные poll-оверлапы схлопываются в unique;
  строки без id → missing_id (здесь 0).
- Знаменатели: aggr%/passive% — от classified; classified_share — от total_rows.

| Пара | total_rows | unique | dup | missing | classified | aggr_ok | passive_ok | ambiguous | indet | no_snap | unverified | aggr% (classified) | passive% (classified) | classified_share (total_rows) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| PRLUSDT     | 120296 | 9539 | 110757 | 0 | 9229 | 9062 | 167 | 79   | 133  | 98  | 0 | 98.1905% | 1.8095% | 7.6719% |
| LTCUSDT     | 118900 | 379  | 118521 | 0 | 192  | 183  | 9   | 0    | 80   | 107 | 0 | 95.3125% | 4.6875% | 0.1615% |
| QUANTUSUSDT | 120000 | 4258 | 115742 | 0 | 2398 | 2257 | 141 | 2    | 1764 | 94  | 0 | 94.1201% | 5.8799% | 1.9983% |

Conservation (с no_snap): unique + missing_id = classified + ambiguous + indet +
no_snap + unverified — выполнено для всех трёх пар: PRLUSDT 9539 = 9229+79+133+98+0;
LTCUSDT 379 = 192+0+80+107+0; QUANTUSUSDT 4258 = 2398+2+1764+94+0. Строгий вид из
ТЗ (unique = classified + ambiguous + indet) сознательно НЕ сходится при
no_snap≠0 (94–107 сделок на пару без валидного снимка ≤30с). Вердикт по всем
парам: aggressor-consistent. Доли classified_share резко различаются (PRL
7.6719%, LTC 0.1615%, QUANTUS 1.9983%), т.к. большую часть total_rows
составляют дубли повторных poll'ов, схлопнутые дедупом по (pair,id); при этом
согласование с агрессором устойчиво у всех трёх.

Дополнительное свидетельство: в приватном потоке `side == order_side` для
всех 21 своих исполнений (100%), а все мои ордера — `type=market` (агрессор).
То есть в приватном потоке side = сторона моего (агрессорского) ордера.

**Ограничения (честно):**
- Даже 98.19% — эмпирика, не доказательство контракта; REST-снимки сдвинуты
  во времени, направление сделки выводилось из цены относительно стакана.
- Прямое сопоставление по trade_id (моя сделка в публичном потоке) НЕ
  выполнено: пагинация публичного API обрывается HTTP 500 после ~100-110
  страниц (проверено 120..500), а мои исполнения старше доступной глубины.
- Документ именно сборки SafeTrade (сериализатор, swagger) не найден: swagger
  404/недоступен, публичная документация отсутствует. Каноническая док.
  Peatio описывает taker_type, которого у SafeTrade нет.

**Статус контракта: side ∈ {buy,sell} публичного потока СОГЛАСУЕТСЯ со
стороной агрессора, но официально НЕ подтверждён** → в opportunity
`side_confirmed=False` сохраняется, направленные opportunity остаются 0.
Для чувствительности можно прогнать модель с двумя ПРЕДПОЛАГАЕМЫМИ
трактовками (aggressor/passive) отдельным сценарием, не меняя manifest и не
называя это confirmed/fills.
