ЧТО ЭТО ТАКОЕ И ЗАЧЕМ
------------------------------------------------------------------------------
Мост — это локальный сервер на машине (Kali VM, 127.0.0.1:8765), который
соединяет двух агентов:
  1) Hermes (этот AI-агент, работает на твоей машине, умеет терминал, файлы,
     скрипты, реальные биржевые API и т.д.);
  2) ChatGPT (OpenAI, работает в браузере/приложении, умеет «думать»,
     писать планы, ревьюить код и отдавать инструкции).

Проблема, которую решает мост: Hermes и ChatGPT живут в разных местах и не
видят друг друга. Раньше приходилось копировать тексты руками. Мост — это
«почтовый ящик» (очередь задач) с веб-интерфейсом для ChatGPT:
  - Hermes кладёт в очередь сообщение (задачу/отчёт);
  - ChatGPT читает его инструментом bridge_get_message;
  - ChatGPT отвечает инструментом bridge_put_reply (или сам создаёт новую
    задачу для Hermes инструментом bridge_put_message);
  - Hermes видит ответ в БД очереди и продолжает работу.

ДВА РЕЖИМА РАБОТЫ
------------------------------------------------------------------------------
РЕЖИМ 1. ОБЫЧНЫЙ ЧАТ (полуавтоматический) — работает уже сейчас
  - Открываешь обычный чат с ChatGPT, куда подключён плагин $hermes
    (Custom MCP connector).
  - ChatGPT видит 6 инструментов моста:
      bridge_get_message    — прочитать задачу Hermes по job_id
      bridge_put_reply      — ответить Hermes по тому же job_id
      bridge_put_message    — отправить Hermes новую задачу (to_hermes)
      bridge_subscribe      — подписаться на события (диагностика/fallback)
      bridge_subscription_status — показать свои подписки
      bridge_unsubscribe    — отключить подписку
  - ВАЖНО: ChatGPT ищет задачи по ПОЛНОМУ job_id, например
      job_bea9aa2fc186f6b7bd5e37fa
    Короткий префикс (job_bea9aa2f) он НЕ находит — всегда передавай полный.
  - Человек остаётся в цепочке: ты (или поллер) передаёшь ChatGPT свежий
    job_id, он читает, отвечает. Это «полуавтомат»: связь мгновенная, но
    запуск требует передачи номера задачи.

РЕЖИМ 2. WORK (автоматический, target) — настройка в процессе
  - ChatGPT Work — это отдельный режим OpenAI (веб), в котором MCP Events
    поддерживаются нативно (в обычном Chat событие до модели не доходит —
    проверено 2026-10-07).
  - В Work ChatGPT сам подписывается на событие hermes.message.created,
    сам просыпается при появлении новой задачи и выполняет цикл
    «прочитать → обработать → ответить» БЕЗ участия человека.
  - Серверная часть уже готова (server/discover, events/list, events/
    subscribe, events/unsubscribe, обогащённый payload — commit 1ad5021).
  - Осталось сделать РЕАЛЬНЫЙ end-to-end тест в Work (см. ниже).

КАК УСТРОЕНО «ПОД КАПОТОМ»
------------------------------------------------------------------------------
- Сервер: bridge_server.py (FastMCP), слушает 127.0.0.1:8765, наружу
  выходит через бесплатный туннель cloudflared:
      https://resort-goto-link-emotional.trycloudflare.com/mcp
  (URL туннеля МЕНЯЕТСЯ при перезапуске cloudflared; после рестарта нужно
  обновить BRIDGE_BASE и переподключить плагин).
- Очередь: bridge_queue.py — задачи с направлением:
      to_chatgpt  — сообщение ChatGPT (создаёт Hermes через bridge_cli put)
      to_hermes   — сообщение Hermes (создаёт ChatGPT через bridge_put_message)
  Плюс idempotency_key (повтор не плодит дубли), lease на захват задач
  воркером, лимит 20 сообщений/мин на владельца.
- Подписки/события: события hermes.message.created публикуются в webhook
  OpenAI (connectors.api.openai.com/webhook/mcp-events/...) ТОЛЬКО для
  to_chatgpt и только после COMMIT задачи. Webhook подписан (Standard
  Webhooks), доставка с retry.
- Поллер: bridge_poller.py (системный cron, каждые 3 мин) — напоминает
  ChatGPT о давних pending-задачах (до 3 раз) и складывает ответы в
  replies_inbox.md. Не напоминает про свои напоминания (фикс 2026-10-07) и
  не работает без активной подписки.
- КЛИ: bridge_cli.py — команды для Hermes/тебя:
      bridge_cli put "текст"   — создать задачу ChatGPT (to_chatgpt) + событие
      bridge_cli list          — список задач (с текстом)
      bridge_cli get JOB_ID    — полная задача с ответом
      bridge_cli subs          — список подписок

КТО ЧТО ДЕЛАЕТ (роли)
------------------------------------------------------------------------------
Hermes:
  - создаёт задачи/отчёты (put), читает ответы (get);
  - обрабатывает входящие задачи от ChatGPT (claim/complete через
    bridge_queue: complete_to_hermes создаёт отчёт to_chatgpt автоматически);
  - держит сервер и туннель живыми, верифицирует код (pytest 113 passed,
    e2e 12/12).

ChatGPT:
  - читает задачи, отвечает, сам создаёт задачи Hermes;
  - в Work — подписывается на события и работает автономно.

Человек (ты):
  - в обычном чате: передаваешь ChatGPT полный job_id, когда нужно
    свериться/получить ревизию;
  - при перезапуске туннеля: переподключаешь плагин (см. ниже);
  - в Work: один раз даёшь фразу на подписку (см. ниже).

ЧТО СДЕЛАТЬ, ЧТОБЫ ЗАРАБОТАЛО (по шагам)
------------------------------------------------------------------------------
ШАГ 1. Проверка, что мост жив:
    curl http://127.0.0.1:8765/ping
  Должен вернуть {"ok":"ok","version":"0.2.0","git_revision":...}.
  Если нет — перезапустить: см. ниже «Перезапуск».

ШАГ 2. Обычный чат (полуавтомат) — уже работает:
  - Открой обычный чат ChatGPT, выбери плагин $hermes (через @/UI).
  - Убедись, что ChatGPT видит bridge_* инструменты (спроси его «какие
    инструменты Hermes ты видишь?»).
  - Дай задачу: «Прочитай job_id = <ПОЛНЫЙ job_id> через bridge_get_message,
    обработай и ответь bridge_put_reply тем же job_id».

ШАГ 3. Work (автомат) — финальный тест:
  - В OpenAI переключись в Work (новый чат), выбери $hermes.
  - После rescan/reconnect плагина на странице плагина должно быть видно
    событие hermes.message.created (рядом с инструментами).
  - Напиши в Work ровно такую фразу (без ручных webhook/secret — их ChatGPT
    передаёт сам):

      «Подпишись через MCP Events на событие hermes.message.created от
      $hermes. Когда приходит событие, прочитай job_id через
      bridge_get_message, обработай задачу и отправь результат Hermes
      через bridge_put_reply. Продолжай делать это для следующих событий,
      пока я не попрошу остановиться.»

  - В логах сервера должны появиться native events/subscribe от Work.
  - Hermes создаёт тестовый to_chatgpt job — Work должен САМ проснуться,
    прочитать и ответить без нового твоего сообщения.
  - После теста: «останови мониторинг» → native events/unsubscribe.
  - Только когда это сработает без твоего участия — режим Work считается
    доказанным.

ШАГ 4. Перезапуск (если сервер/туннель умер):
  - Туннель: cloudflared (проверить: pgrep -af cloudflared). После рестарта
    URL меняется — узнать новый: посмотреть вывод процесса cloudflared
    (строка trycloudflare.com).
  - Сервер: kill старого bridge_server.py, запустить заново с
    BRIDGE_BASE=<новый https-URL> (обычно это делает Hermes по просьбе).
  - Плагин: в ChatGPT переподключить Custom MCP connector на новый URL
    (обязательно с /mcp на конце! например
    https://resort-goto-link-emotional.trycloudflare.com/mcp).
  - После переподключения НАЖАТЬ rescan/reconnect, чтобы обновились
    инструменты и события.

ЧАСТЫЕ ОШИБКИ (чтобы не наступать дважды)
------------------------------------------------------------------------------
1. Обрезанный job_id: ChatGPT НЕ находит задачи по короткому префиксу.
   Всегда полный: job_9286282abbe60c9ad8591bd9 (40 симв.).
2. URL плагина без /mcp: если задать https://...trycloudflare.com (без /mcp),
   MCP-инструменты не появятся. Нужно .../mcp. (Фикс на сервере —
   нормализация resource — уже внесён, но URL всё равно указывай с /mcp.)
3. Инструменты пропали после обновления сервера: коннектор кэширует список
   tools/events — нужен rescan/reconnect плагина или новый чат.
4. Push-события в ОБЫЧНОМ чате: не доходят до модели (проверено 2026-10-07).
   Обычный чат = pull по job_id. Work = push (там и живёт автоматика).
5. Поллер каскадом плодил напоминания — исправлено (list_jobs отдаёт text,
   поллер не напоминает про свои напоминания и без активной подписки).
   Если снова увидишь тысячи [АВТО-НАПОМИНАНИЕ] в list — сообщи Hermes.
