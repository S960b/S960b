# Horse Racing: ход решения

[English](solve.md)

## 1. Задача

В приложении скачек игрок начинает с 10 очков и получает VIP при 500. Ставки должны закрываться после старта забега, но проверка происходит раньше чтения тела HTTP-запроса.

Материалы: Rust/Axum `src/main.rs`, `Cargo.toml`, HTML client; direct Git-bridge run report.

## 2. Разбор

Маршрут Axum использует `middleware::from_fn_with_state(..., betting_open)`. Middleware читает `timer < 30` до вызова `next.run(request)`. Сам хендлер `bet` позже разбирает `Json<BetRequest>`. Можно отправить заголовки POST с `Content-Length: 80` и задержать тело. Проверка пропустит запрос до таймера 30, после чего хендлер будет ждать данные. Одновременно `/api/state` отдаёт позиции 16 лошадей, и во время забега уже виден фаворит.

## 3. Последовательность действий

1. На соединении A отправить только заголовки `POST /api/bet`, включая `Content-Length: 80` и `Content-Type: application/json`. Тело не передавать.
2. На соединении B опрашивать `/api/state` до начала забега. Агент использовал условия `lead >= 50` и отрыв от второго места минимум 10.
3. Дослать на A JSON `{\"horse\":N,\"amount\":M}`, заполнив пробелами до 80 байт. Middleware уже сработал, поэтому ставка принимается при `timer >= 30`.
4. После финиша забрать выплату, ставить весь банк на следующем забеге.
5. По живому логу: `10 -> 20 -> 40 -> 80 -> 160 -> 320 -> 640` за шесть гонок. После 500 очков флаг открывается в `/api/state`.

## 4. Что подтверждено

Исходник подтверждает порядок проверки и разбора JSON, состояние забега и VIP-порог. Отчёт агента фиксирует отправку задержанного тела, HTTP 200 уже на забеге и рост банка. Между двумя отчётами есть расхождение в одной букве флага, поэтому строка замаскирована.

**Результат:** 1 принятый флаг(а), в открытом репозитории скрыты (`PP{...}`).

## 5. Что не сохранилось

Файла с точным сокетным эксплойтом в архиве нет. Последовательность и пороги сохранены в отчёте, полного сетевого дампа нет.

## 6. Меры защиты

Проверять время внутри хендлера после приёма полного тела запроса и в одной синхронизированной операции с записью ставки. Или привязывать решение к доверенному времени приёма сообщения.
