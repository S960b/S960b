# Matryoshka: вложенный ELF и обращение четырёх CRC32

[English](solve.md)

## 1. Извлечение внутреннего слоя

Раздатка содержит stripped ELF x86-64 `matryoshka`. Бинарь создаёт анонимный исполняемый файл через `memfd_create("stage2", MFD_CLOEXEC)`, записывает в него **154 328 байт** и выполняет внутреннюю программу. Трассировка показала:

```bash
strace -f -e trace=memfd_create,execve,write -s 60 ./matryoshka
# memfd_create("stage2", MFD_CLOEXEC) = 10
# write(10, "\\177ELF...", 154328) = 154328
```

Из записанных в трассу байтов извлекли `stage2.bin`, исследовали его код и `.rodata`. Внутренний бинарь спрашивал пароль в **шестнадцатеричном формате**; произвольную текстовую строку отвергал с `Invalid hex`.

## 2. Четыре уравнения CRC32

Пароль состоит из **16 байт**. Для каждого блока по четыре байта проверяется CRC32:

```python
targets = [0x6d795f63, 0x30306c5f, 0x70343473, 0x77307264]
```

Для входа фиксированной длины CRC32 — **аффинная функция над GF(2)**. Чтобы получить линейную часть, вычитаем XOR-ом CRC от четырёх нулевых байт:

```text
C0 = CRC32(00 00 00 00)
L(x) = CRC32(x) XOR C0
cols[j] = CRC32(1 << j в виде 4 little-endian байт) XOR C0
XOR_j (bit[j] * cols[j]) = target XOR C0
```

Составляем 32 уравнения по битам, решаем исключением Гаусса над GF(2). Повторяем для четырёх блоков. Реализация — [`scripts/solve_crc.py`](scripts/solve_crc.py):

```bash
python3 scripts/solve_crc.py
```

Результат:

```text
password hex: c667c58c3b02d6c91b8def4fdd1bc5f3
CRC[0:4]   = 6d795f63
CRC[4:8]   = 30306c5f
CRC[8:12]  = 70343473
CRC[12:16] = 77307264
```

Это 16 байт бинарных данных, которые при вводе записываются **32 символами hex**. Видимая строка `my_c00l_p44sw0rd` относится к байтам CRC-целей, но не является корректным паролем.

## 3. Проверка на программе и принятый флаг

В сохранённом сеансе запущен извлечённый внутренний ELF:

```bash
printf 'c667c58c3b02d6c91b8def4fdd1bc5f3\n' | ./stage2.bin
```

Результат:

```text
Enter password: Password correct!
Here is your flag: PP{th3r3_1s_4_b1n4ry_1n_my_b1n4ry?!}
```

В дополнительном пакете записан тот же результат при передаче пароля исходному `matryoshka`:

```bash
printf 'c667c58c3b02d6c91b8def4fdd1bc5f3\n' | ./matryoshka
```

При отправке флага платформа вернула **HTTP 200, `{"status":1}`**. Задача решена.

## 4. Зачем использовали XOR на 36 байтах

При разборе `stage2.bin` нашли 36 байт шифртекста по **смещению файла `0x1b560`**. К ним применяется повторяющийся 16-байтный XOR-ключ — восстановленный пароль:

```python
data = open("stage2.bin", "rb").read()
cipher = data[0x1b560:0x1b560 + 36]
password = bytes.fromhex("c667c58c3b02d6c91b8def4fdd1bc5f3")
flag = bytes(c ^ password[i % 16] for i, c in enumerate(cipher))
print(flag)
```

Эта отдельная проверка напечатала **тот же флаг**. Однако после ввода правильного пароля сама программа проверяет его и выводит флаг. Ручное применение XOR — независимое подтверждение механизма, а не обязательный дополнительный шаг.

## 5. Вывод

Один CRC32 над 32 входными битами превращается в 32 обратимых аффинных уравнения. Разбиение пароля на четыре блока не даёт криптографической стойкости. Вложенные ELF и повторяющийся XOR усложняют анализ, но не защищают секрет.
