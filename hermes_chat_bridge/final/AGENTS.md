# Инструкция для ChatGPT и MT в этом репозитории

**В каждом новом чате перед работой с мостом прочитать [CHATGPT_GIT_BRIDGE.md](CHATGPT_GIT_BRIDGE.md).** Это рабочая памятка с точным JSON, API, preflight, публикацией и диагностикой. Не полагаться на память из старого диалога.

1. Проверить **актуальные** MCP-инструменты. 6 ноября 2026 были: `dialog_create`, `dialog_creation_status`, `dialog_list`, `dialog_index`, `dialog_health`, `dialog_notice`. Исторические `dialog_view`/`dialog_append` отсутствовали в этой сессии; вызывать только если реально появились.
2. `dialog_index` не отдаёт тела. Содержимое читать из GitHub по точному HEAD ветки `dialogs/<task_id>`. `dialog_notice` только подтверждает наличие ранее записанного Git-коммита; это НЕ доставка MT.
3. Если пользователь сообщил `task_id`, продолжать только эту ветку. Никаких новых ID и legacy `bridge_*` / Hermes Queue.
4. **До любого Git POST:** validate полный snapshot и планируемое сообщение. Read-only `scripts/preflight_chatgpt_append.py` использует основной парсер. Timestamp `YYYY-MM-DDTHH:MM:SSZ`, не JS milliseconds; body максимум 64 KiB.
5. Если `dialog_append` нет: подготовить и проверить ровно два изменённых файла (`messages/<seq>.chatgpt.json` + `state.json`), commit с одним parent=current HEAD, только fast-forward CAS без force. Проверить candidate **до** движения ref. Затем `dialog_notice(task_id,head,message_id,seq)`.
6. `observed:true` ≠ `delivered`. При неизвестном исходе — только чтение и сверка того же message ID; не дублировать запись/исполнение. Никаких правок production services, secrets, SQLite, MT state без поручения.

**Инцидент 9 ноября 2026 (важно для обоих агентов).** При прямом Git POST в NEWS Phase 4 v2 была ошибочно записана `messages/21.chatgpt.json` с `created_at_utc: "2026-11-09T15:45:47.561Z"`. `validate_timestamp()` отвергает эту строку, и **одна невалидная метка делает недоступной всю историю** (даже если Git-ветка и сообщения существуют). По разрешению владельца исправлено **только поле timestamp** новым fast-forward repair-коммитом `bd019713bd03b1b823272f411c9750360475db02`; исходный Git-коммит не удалялся. Перед **любой** публикацией проверять `YYYY-MM-DDTHH:MM:SSZ` (UTC, без миллисекунд и смещения): JS `new Date().toISOString().slice(0,19) + "Z"`, Python `datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")`. Использовать `scripts/preflight_chatgpt_append.py`/эквивалентную полную валидацию до Git POST, затем проверять candidate snapshot до CAS. При `authority_unavailable` сначала проверить Git JSON и snapshot через GET, не диагностировать падение сервиса только по общему коду и **не создавать дубль** сообщения. Прямой repair старого сообщения допустим только по отдельному разрешению владельца; обычный протокол остаётся append-only. Нормализацию формата в коде обсудить отдельно, сейчас код не менялся.

**Ограничение:** локальный preflight не является server-side branch protection. Ручной путь GitHub не заменяет гарантий общей authority.
