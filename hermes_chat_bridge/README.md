# Hermes Chat Bridge — мост между ChatGPT и локальным агентом

**Назначение:** отдельный инфраструктурный проект, соединяющий ChatGPT с локальным агентом **MultiTool (MT / Hermes)** на компьютере пользователя. ChatGPT готовит задачи, пишет/анализирует код и проверяет результаты; локальный агент выполняет команды, работает с файлами и возвращает отчёты. Благодаря мосту это один последовательный процесс с историей, а не ручная пересылка сообщений.

**Это не торговое исследование.** Каталог вынесен из `research/` в корень портфолио 10 ноября 2026 года.

## Как работает современный Git-мост

```text
ChatGPT
   │  MCP Hermes: dialog_create / dialog_index / dialog_health
   │  GitHub connector: проверенная публикация сообщения (CAS)
   │  MCP Hermes: dialog_notice (наблюдение за уже записанным commit)
   ▼
Приватный GitHub: S960b/agent-dialogs
   └── dialogs/<task_id>/
       ├── task.json
       ├── state.json
       └── messages/<seq>.<actor>.json
   ▼
Локальная authority + MT Git Inbox
   ▼
Локальная сессия MultiTool/Hermes на компьютере
   │
   └── отчёт MT в той же Git-ветке → ChatGPT читает ответ
```

Одна задача соответствует одной Git-ветке `dialogs/<task_id>`. `main` приватного репозитория содержит **исходный код и документацию**, но не живые диалоги. Локальный Taskboard показывает задачи и историю; штатный адрес панели на компьютере — `http://127.0.0.1:8787` (не публичный адрес).

**Важно:** `dialog_index` отдаёт индекс, а не тело сообщения; `dialog_notice` подтверждает наблюдение уже опубликованного commit, но само сообщение **не создаёт** и не гарантирует, что MT его получил. Порядок действий и обязательная валидация указаны в текущей [памятке](https://github.com/S960b/agent-dialogs/blob/main/CHATGPT_GIT_BRIDGE.md). Не используйте устаревшие `bridge_get_message`, `bridge_put_reply`, `job_id` или вымышленные `dialog_view` и `dialog_append` без проверки доступного интерфейса.

## Что лежит в этом публичном каталоге

- [CURRENT_STATE.md](CURRENT_STATE.md) — короткая актуальная карта проекта, без утверждений о непроверенном состоянии машины
- [MIGRATION.md](MIGRATION.md) — история переноса и объяснение совместимости путей
- [legacy/](legacy/) — **сохранённая без изменения историческая реализация 15 октября 2026 года**: старый SQLite/MCP bridge, старые `README.md`, `CURRENT_STATE.md`, `readmefirst.txt`, скрипты, tests, systemd, отчёты

**ВНИМАНИЕ:** документы в `legacy/` описывают октябрьский этап с SQLite-очередью, OAuth и Tailscale Funnel; в текущем ноябрьском Git-протоколе это **не руководство по установке**. При этом часть старого кода (например, внешний `bridge_server.py` как транспорт MCP) могла остаться частью локальной интеграции после P34. Нельзя объявлять все старые Python-файлы ненужными или удалять их на Kali без проверки реальных сервисов.

В публичном репозитории история сохранена для понимания развития проекта. **Единственный источник актуальных правок Git-моста — приватный `S960b/agent-dialogs`**, а не папка `legacy/` здесь.
