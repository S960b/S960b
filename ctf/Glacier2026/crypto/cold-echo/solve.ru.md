# Cold Echo — восстановление подписанного полинома по произведениям P(u)P(u⁻¹)

[English version](solve.md)

## 1. Что дано

Оригинальный архив содержит `README.md` и `archive.json` с параметрами:

```text
p = 17179869143
degree = 42
batch = bed64d3525599836
trace: 42 пары [u, P(u)·P(u⁻¹) mod p]
forward: [89, 11033196826]
public_key_pem: открытый ключ ECDSA P-256
receipt_der_b64: DER-подпись ECDSA с SHA-256
flag_mask_b64: маска флага
```

Нужно восстановить **подписанный** многочлен `P` точной степени 42, для которого `P(1)=1`. Одних 42 произведений недостаточно для однозначного определения `P`, но нормировка, прямое измерение и ECDSA-подпись устраняют неопределённость.

## 2. Линеаризация через самосопряжённый S

Обозначим `P(X)=Σa_iX^i` и `rev(P)(X)=X^42P(1/X)`. Тогда

```text
L(X)=P(X)P(X⁻¹)=c₀+Σ_{d=1}^{42}c_d(X^d+X^(-d))
S(X)=X^42L(X)=P(X)rev(P)(X).
```

Из каждой пары `[u_j,r_j]` получаем **линейное** сравнение

```text
c₀+Σ_{d=1}^{42}c_d(u_j^d+u_j^(-d))=r_j (mod p).
```

42 строки, 43 неизвестных. Самописный метод Гаусса над `F_p` дал **ранг 42 и одно свободное направление**. Неудачный вариант `sympy.Matrix.rank()` применял рациональную арифметику и завис более чем на 120 секунд.

Пусть `c=c_p+λc_n`, где `c_p` — частное решение, `c_n` — базис ядра. Из `P(1)=1` выводим `S(1)=1`, то есть

```text
W(c)=c₀+2Σ_{d=1}^{42}c_d=1,
λ=(1-W(c_p))/W(c_n) mod p.
```

Получено **`λ=1922965990`**. Собран `S(X)` степени 84 с 85 палиндромными коэффициентами.

## 3. 84 корня и 42 обратные пары

Кодом проверены:

```text
gcd(S,S')=1
deg gcd(S,X^p-X)=84
```

Следовательно, все 84 корня различны и находятся в `F_p`. Скрипт `roots.py` применяет модульную степень и полиномиальный НОД, а `cz.py` использует разложение Кантора–Цассенхауса (случайное `X+a`, степень `(p-1)/2`, НОД и рекурсивное деление).

В первой версии Кантора–Цассенхауса ошибочно брали **остаток** от деления `f` на найденный множитель `g` вместо **частного**. Поэтому получался один корень; исправленный алгоритм извлёк 84.

Из симметрии `S` следует, что для каждого `r` есть `r⁻¹`. `pairs.py` нашёл **42 пары**. Корней `1` и `−1` нет.

## 4. Meet-in-the-middle вместо 2^42

Чтобы построить кандидата `P`, берём один корень `x_i` из каждой пары:

```text
P(X)=∏(X-x_i)/∏(1-x_i) mod p.
```

Это автоматически обеспечивает `P(1)=1`. Прямое измерение `P(89)` даёт мультипликативное условие:

```text
∏ᵢ (89-x_i)/(1-x_i) ≡ 11033196826 (mod p).
```

Перебор `2^42` огромен, но разделив 42 пары на 21 и 21, получаем две таблицы порядка `2^21`. Для произведения правой половины `R` ищем в словаре левой значение `11033196826/R` по модулю `p`.

Скрипт `mitm.py` нашёл **243 кандидата**. Это ещё не готовый ответ: прямое измерение допускает много разных наборов корней.

## 5. Единственность по ECDSA

Для каждого масочного набора `solve.py` восстанавливает коэффициенты `P` и проверяет:

- степень ровно 42, `P(1)=1`;
- `P(89)=11033196826`;
- `P(X)rev(P)(X)=S(X)`;
- валидность ECDSA-подписи под **точным каноническим чеком**.

Формат чека:

```text
GLACIER-COLD-ECHO-v1
bed64d3525599836
17179869143 42
<42 строки u reading в исходном порядке>
89 11033196826
<a0 a1 ... a42 через пробел, по возрастанию степени>
```

Каждая строка заканчивается LF, **включая последнюю**. Целые пишутся десятично без ведущих нулей. Подпись — DER ECDSA P-256, хеш SHA-256.

**Ровно один из 243 вариантов** прошёл `VerifyingKey.verify`. В исходном выводе `found: True` и весь подписанный чек; повторный прогон в архиве воспроизвёл тот же результат.

## 6. Раскрытие флага

Формула из оригинального README:

```python
mask = base64.b64decode(A['flag_mask_b64'])
pad = hashlib.sha256(b"cold-echo-flag-pad-v1\n" + msg.encode()).digest()
body = bytes(x^y for x,y in zip(mask,pad))
flag = "gctf{" + base64.urlsafe_b64encode(body).decode().rstrip("=") + "}"
```

Получен флаг в правильном формате; участник подтвердил принятие платформой. В публичном GitHub полное значение скрыто, но в частных `FLAG.txt` и `evidence/cold_echo_result.json` оно сохранено.

## 7. Неудачные гипотезы, доказательства и воспроизведение

- `sympy.Matrix.rank()` зависал на 42×43 матрице при рациональной арифметике; модульный Гаусс выполнялся быстро.
- В исходном `cz.py` путали остаток и частное, получали один корень; исправлено.
- Прямой выбор одного из каждой пары потребовал бы `2^42` вариантов; MITM сократил вычисления до двух таблиц `2^21`.
- Верификация опирается на **оригинальный публичный ключ ECDSA и подпись**; никакой подмены ключей нет.

В `glacierctf_cold-echo_materials.zip` сохранены оригинальные данные, все использованные скрипты, числовые контрольные точки, полный найденный `P`, текст чека и `solver_run.log` — это повторный детерминированный запуск при упаковке, не исходный лог первого решения.

Задача полностью **офлайновая**. Для воспроизведения достаточно Python и библиотеки `ecdsa`; сеть и активный сервис CTF не нужны. Подтверждённый пользователем статус: **Solved / Flag accepted by platform**.
