ЧТО ЭТО ТАКОЕ И ЗАЧЕМ
------------------------------------------------------------------------------
Мост — это локальный сервер на машине (Kali VM, 127.0.0.1:8765), который
соединяет двух агентов:
  1) Hermes (этот AI-агент, работает на твоей машине, умеет терминал, файлы,
     скрипты, реальные биржевые API и т.д.);
  2) ChatGPT (OpenAI, работает в браузере/приложении, умеет «думать»,
     писать планы, ревьюить код и отдавать инструкции).

Проблема, которую решает мост: Hermes и ChatGPT живут в разных местах и не
видят друг друга. Мост — это «почтовый ящик» (очередь задач) с веб-интерфейсом:
  - Hermes кладёт в очередь сообщение (задачу/отчёт);
  - ChatGPT читает его инструментом bridge_get_message;
  - ChatGPT отвечает инструментом bridge_put_reply (или сам создаёт новую
    задачу для Hermes инструментом bridge_put_message);
  - Hermes видит ответ в БД очереди и продолжает работу.

ВСЯ РАБОТА ХРАНИТСЯ В ОДНОМ ФАЙЛЕ-БАЗЕ:
  ~/.local/state/hermes-bridge/pilot-20261004T140717Z/pilot.db

включая BRIDGE_BASE и пароль владельца; файл закрыт правами 600, его нельзя
публиковать и нельзя светить в переписке).

ДВА РЕЖИМА РАБОТЫ
------------------------------------------------------------------------------
РЕЖИМ 1. ОБЫЧНЫЙ ЧАТ (полуавтоматический) — работает
  - Открываешь обычный чат с ChatGPT, куда подключён плагин $hermes
    (Custom MCP connector).
  - ChatGPT видит инструменты моста:
      bridge_get_message    — прочитать задачу Hermes по job_id
      bridge_put_reply      — ответить Hermes по тому же job_id
      bridge_put_message    — отправить Hermes новую задачу (to_hermes)
      bridge_subscribe      — подписаться на события (диагностика/fallback)
      bridge_subscription_status — показать свои подписки
      bridge_unsubscribe    — отключить подписку
  - ВАЖНО: ChatGPT ищет задачи по ПОЛНОМУ job_id. Формат job_id с 2026-10-14:
      {метка}_{8hex}.job   например  test_1f1a1e9a.job
    Короткий префикс (test_1f1a1e) он НЕ находит — всегда передавай полный.
  - Человек остаётся в цепочке: ты (или таск-борд) передаёшь ChatGPT свежий
    job_id, он читает, отвечает. Это «полуавтомат».

РЕЖИМ 2. WORK (автоматический, target) — настройка в процессе
  - ChatGPT Work — отдельный режим OpenAI (веб), в котором MCP Events
    поддерживаются нативно (в обычном Chat событие до модели не доходит).
  - В Work ChatGPT сам подписывается на событие hermes.message.created,
    сам просыпается при появлении новой задачи и выполняет цикл
    «прочитать → обработать → ответить» БЕЗ участия человека.

КАК УСТРОЕНО «ПОД КАПОТОМ»
------------------------------------------------------------------------------
- Сервер: bridge_server.py (FastMCP), слушает 127.0.0.1:8765 (только
  localhost), наружу выходит через Tailscale Funnel:
      https://kali.tail12eeb2.ts.net/mcp
  (адрес постоянный; BRIDGE_BASE в pilot_environment.private.json =
  https://kali.tail12eeb2.ts.net — OAuth issuer, Host-allowlist и redirect
  строятся от него).
- Очередь: bridge_queue.py — задачи с направлением:
      to_chatgpt  — сообщение ChatGPT (создаёт Hermes через bridge_cli put)
      to_hermes   — сообщение Hermes (создаёт ChatGPT через bridge_put_message)
  Плюс idempotency_key (повтор не плодит дубли), lease на захват задач
  воркером, лимит сообщений/мин на владельца.
- Подписки/события: события hermes.message.created публикуются в webhook
  OpenAI (connectors.api.openai.com/webhook/mcp-events/...) ТОЛЬКО для
  to_chatgpt и только после COMMIT задачи. Webhook подписан (Standard
  Webhooks), доставка с retry. ВАЖНО: вебхуки НЕ зависят от адреса моста —
  после смены схемы доступа их не нужно пересоздавать.
- Таск-борд: taskboard.py (сервис hermes-taskboard.service), открывается
  локально: http://127.0.0.1:8787. Показывает задачи (автообновление 5с),
  фильтры, постоянный адрес моста с кнопкой «⧉ копировать» и у КАЖДОГО
  job_id кнопку «⧉» для быстрого копирования id (для пересылки ChatGPT).
- КЛИ: bridge_cli.py — команды для Hermes/тебя:
      bridge_cli put "текст" [queue] [label]  — создать задачу ChatGPT
      bridge_cli list          — список задач (с текстом)
      bridge_cli get JOB_ID    — полная задача с ответом
      bridge_cli subs          — список подписок
  Запуск: BRIDGE_DB_PATH=... ~/.venvs/bridge-clean/bin/python bridge_cli.py ...

КТО ЧТО ДЕЛАЕТ (роли)
------------------------------------------------------------------------------
Hermes:
  - создаёт задачи/отчёты (put), читает ответы (get);
  - обрабатывает входящие задачи от ChatGPT (claim/complete через
    bridge_queue: complete_to_hermes создаёт отчёт to_chatgpt автоматически);
  - держит сервер, таск-борд и Funnel живыми, верифицирует код после правок.

ChatGPT:
  - читает задачи, отвечает, сам создаёт задачи Hermes;
  - в Work — подписывается на события и работает автономно.

Человек (ты):
  - держишь включённым tailscaled (автозапуск уже настроен);
  - в обычном чате: передаёшь ChatGPT полный job_id (удобно — кнопка «⧉»
    в таск-борде), когда нужно свериться/получить ревизию;
  - если мост «молчит» — проходишь чек-лист ниже.

ЧТО ПРОВЕРИТЬ ЧЕЛОВЕКУ (чек-лист, если что-то не работает или после ребута)
------------------------------------------------------------------------------
1. Мост жив локально:
      systemctl --user is-active hermes-bridge hermes-taskboard   -> active active
      curl http://127.0.0.1:8765/ping                             -> {"ok":"ok",...}
2. Публичный адрес отвечает (Tailscale Funnel):
      curl https://kali.tail12eeb2.ts.net/ping                    -> {"ok":"ok",...}
   Если таймаут — подожди 5–10 сек и повтори (первый запрос после старта
   Funnel выпускает TLS-сертификат).
3. Funnel включён:
      tailscale funnel status          -> строка про https://kali.tail12eeb2.ts.net
   Если «No serve config»:
      sudo tailscale funnel --bg --https=443 8765
4. Tailscale автозапуск (чтобы пережил ребут):
      systemctl is-enabled tailscaled  -> enabled
   Если нет: sudo systemctl enable --now tailscaled
5. Плагин ChatGPT подключён к правильному URL:
      https://kali.tail12eeb2.ts.net/mcp   (обязательно с /mcp на конце!)
   Если инструменты пропали: в настройках плагина нажать rescan/reconnect
   (или пересоздать коннектор с этим URL и заново пройти OAuth).
6. OAuth-доступ: логин владельца в форме входа — пользователь owner, пароль
   из файла ~/.local/state/hermes-bridge/pilot-20261004T140717Z/
   pilot_environment.private.json (ключ BRIDGE_PASS; файл 600).
7. Таск-борд показывает адрес и задачи: http://127.0.0.1:8787
   (кнопка «⧉» у job_id копирует id в буфер — удобно для пересылки ChatGPT).

ЧТО СДЕЛАТЬ, ЧТОБЫ ЗАРАБОТАЛО (по шагам)
------------------------------------------------------------------------------
ШАГ 1. Проверка, что мост жив:
    curl http://127.0.0.1:8765/ping
  Должен вернуть {"ok":"ok","version":"0.2.x","git_revision":...}.
  Если нет — перезапустить: systemctl --user restart hermes-bridge.

ШАГ 2. Обычный чат (полуавтомат) — уже работает:
  - Открой обычный чат ChatGPT, выбери плагин $hermes (через @/UI).
  - Убедись, что ChatGPT видит bridge_* инструменты (спроси его «какие
    инструменты Hermes ты видишь?»).
  - Дай задачу: «Прочитай job_id = <ПОЛНЫЙ job_id> через bridge_get_message,
    обработай и ответь bridge_put_reply тем же job_id».
  - Полный job_id возьми в таск-борде (кнопка ⧉) или из bridge_cli list.

ШАГ 3. Work (автомат) — финальный тест:
  - В OpenAI переключись в Work (новый чат), выбери $hermes.
  - После rescan/reconnect плагина на странице плагина должно быть видно
    событие hermes.message.created (рядом с инструментами).
  - Напиши в Work фразу:
      «Подпишись через MCP Events на событие hermes.message.created от
      $hermes. Когда приходит событие, прочитай job_id через
      bridge_get_message, обработай задачу и отправь результат Hermes
      через bridge_put_reply. Продолжай делать это для следующих событий,
      пока я не попрошу остановиться.»
  - Hermes создаёт тестовый to_chatgpt job — Work должен САМ проснуться,
    прочитать и ответить без нового твоего сообщения.
  - После теста: «останови мониторинг».

ШАГ 4. Перезапуск (если сервер умер):
  - Мост: systemctl --user restart hermes-bridge
  - Таск-борд: systemctl --user restart hermes-taskboard
  - Funnel (если «No serve config»): sudo tailscale funnel --bg --https=443 8765
  - Tailscale (если нода вышла): sudo tailscale up
    (логин через GitHub, аккаунт S960b)
  - Адрес НЕ меняется: https://kali.tail12eeb2.ts.net/mcp — плагин
    переподключать не нужно (разве что сделать rescan/reconnect).

ЧАСТЫЕ ОШИБКИ (чтобы не наступать дважды)
------------------------------------------------------------------------------
1. Обрезанный job_id: ChatGPT НЕ находит задачи по короткому префиксу.
   Всегда полный: test_1f1a1e9a.job. Копируй через кнопку ⧉ в таск-борде.
2. URL плагина без /mcp: если задать https://kali.tail12eeb2.ts.net (без
   /mcp), MCP-инструменты не появятся. Нужно .../mcp.
3. Инструменты пропали после обновления сервера: коннектор кэширует список
   tools/events — нужен rescan/reconnect плагина или новый чат.
4. Push-события в ОБЫЧНОМ чате: не доходят до модели. Обычный чат = pull по
   job_id. Work = push (там и живёт автоматика).
5. Публичный адрес не отвечает после ребута: проверь п.1–4 чек-листа
   (tailscaled enabled, funnel включён, первый запрос — с повтором).
