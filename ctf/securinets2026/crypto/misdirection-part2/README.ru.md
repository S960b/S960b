# Misdirection: Part 2 (crypto)

Задача про WebAuthn и ECDSA. Дано: исходники сервиса с ботом (`bot.js`, `authenticator.js`,
`auth-flow.js`, `config.js`), серверная часть на Rust (`admin.rs`) с эндпоинтом `/report` и
шифротекст подсказки на 64 байта.

В чём ошибка:

- Бот подписывает вход по WebAuthn с nonce, который не случаен: `k = SHA256(rpId)`, где `rpId`
  это домен входа. Домен публичный, значит nonce известен заранее.
- Функция `forgeAuthentication` выставляется в страницу через `page.exposeFunction` и принимает
  `rpId` и `challenge` из страницы, то есть страница атакующего сама выбирает, что подписывать.
- Обработчик `/report` проверяет только префикс строки через `starts_with`, поэтому ссылка вида
  `https://frontend@attacker/auth` проходит проверку, а после замены префикса ведёт на хост
  атакующего.

Что получилось:

- Две подписи с разными `rpId` дали один и тот же приватный ключ по формуле
  `d = (s*k - z) * r^-1 mod n`.
- Ключ проверен по публичному ключу из `init.sql`: координаты `x` и `y` совпали.
- Подсказка расшифрована AES-256-ECB, ключ это SHA-256 от hex-записи `d` в нижнем регистре.
- Выравнивание нестандартное: добавлено 28 байт со значением 28, обычный PKCS7 на блоке 16 байт
  такое не допускает, поэтому снимается вручную.

Файлы:

- `scripts/solve_misdir.py` - сборщик подписей и восстановление ключа, запускается в трёх шагах
- `scripts/verify_offline.py` - офлайн-проверка: публичный ключ, формула, расшифровка
- `scripts/selftest.py` - самопроверка формулы на синтетических подписях
- `assets/authenticator.js` - подпись с детерминированным nonce
- `assets/bot.js`, `assets/auth-flow.js`, `assets/config.js` - бот и его настройки
- `assets/admin.rs` - обработчик `/report` с проверкой префикса
- `assets/hint_ciphertext.hex` - шифротекст подсказки

Полный путь решения описан в `solve.ru.md`.
