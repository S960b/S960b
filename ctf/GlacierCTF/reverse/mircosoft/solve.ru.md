# mircosoft — расшифровка привязанной к железу Windows-лицензии по дампу администратора

[English version](solve.md)

**GlacierCTF 2026 · Reverse / Windows · 50 баллов · Решено**

## 1. Исходное условие и файлы

В оригинальном `mircosoft (1).tar.gz` лежат:

```text
mircosoft/mircosoft.exe       27136 байт
mircosoft/license.bin          104 байта
mircosoft/admin_machine.dmp  50328 байт
mircosoft/sha256sum             248 байт
```

Все три SHA-256 из `sha256sum` совпали. `mircosoft.exe` — защищённый **Windows PE32+ x86-64**, в предыдущем исследовании отмечены шифрование вложенного PE и anti-debug. Ранее вложенный модуль удалось распаковать, разобрать его проверку лицензии, вычислить правильную контрольную сумму и расшифровать флаг. Сохранился **оригинальный рабочий финальный скрипт**, но `unpacked_pe.bin` и скрипт первоначальной распаковки не входили в handout и не сохранились среди доступных файлов.

## 2. Формат license.bin

104-байтовый файл начинается с `MSLC`:

| Смещение | Длина | Значение |
| --- | ---: | --- |
| `0x00` | 4 | Сигнатура `MSLC` |
| `0x04` | 4 | Версия / служебные данные |
| `0x08` | 16 | MAC аппаратного отпечатка |
| `0x18` | 8 | Nonce гаммы |
| `0x20` | 64 | 8 зашифрованных блоков по 8 байт |
| `0x60` | 8 | Хвостовые данные, оригинальный дешифратор не использует |

MAC в исходном заголовке: `8305d5d5c5316f76bd27ddbbc5221f56`. Прежний успешный запуск рассчитанного MAC показал то же значение. В текущем сеансе сравнение не повторено, так как в архиве нет четырёх секретных ключей распакованного PE.

## 3. Структура MiniDump

`admin_machine.dmp` — настоящий Windows **MiniDump** с сигнатурой `MDMP`, пятью потоками и `MemoryListStream` (тип 5). Поток содержит **7 регионов**:

| Файл | Виртуальный адрес | Размер |
| --- | --- | ---: |
| `region0.bin` | `0x7ffe0000` | 4096 |
| `region1.bin` | `0x1c000000000` | 8192 |
| `region2.bin` | `0x20000000000` | 16384 |
| `region3.bin` | `0x21000000000` | 8192 |
| `region4.bin` | `0x22000000000` | 4096 |
| `region5.bin` | `0x7ff000000000` | 4096 |
| `region6.bin` | `0x7ff000001000` | 4096 |

Написан [scripts/extract_minidump.py](scripts/extract_minidump.py), который без сторонних библиотек читает MDMP, обходит директорию потоков, проверяет границы и извлекает все `region*.bin`. На приложенном дампе эти семь регионов **получены повторно**.

## 4. Пять аппаратных идентификаторов

Сохранённый `solve.py` выбирает фрагменты в строгом порядке:

| Параметр | Где искать | Байты | Фактическое значение |
| --- | --- | ---: | --- |
| CPUID brand string | `region0+0x274` | 48 | `Intel(R) Core(TM) Ultra 7 155H` + нулевое дополнение |
| Серийный номер тома | `region4+0x48` | 4 | `914c8dd4` |
| MachineGuid реестра | `region1+0x500` | 36 | `658c05ff-e49e-40aa-b041-9a5f56886dea` |
| SMBIOS UUID | `region2+0x55` | 16 | `3c31a857b2b700488ce185385968c8a8` |
| MAC сетевой карты | `region3+0x198` | 6 | `52540036e664` |

Всего **110 байт**. SHA-256 их конкатенации, вычисленный независимо из исходного дампа:

```text
9887f856a75c76842491cd7fff0ee47410c3dc97cebeb71c8cc6db624b24c238
```

Нельзя терять завершающие нулевые байты CPUID, представлять UUID как строку вместо исходных 16 байт или менять порядок блоков: из-за этого MAC станет другим.

## 5. Четыре ключа из распакованного PE

В предыдущем решении из вложенного PE были извлечены **четыре ключа по 16 байт** из секции `.data` (RVA `0x6000`, файловое смещение `0x3e00`). `scripts/solve.py` считывает

```python
D=exe[0x3e00:]
keys=[D[16*i:16*i+16] for i in range(4)]
```

Здесь `exe` — **не внешняя `mircosoft.exe`**, а отдельно распакованный `unpacked_pe.bin`. Это принципиально: по одному оригинальному маленькому PE выполнить этот шаг нельзя.

## 6. TEA-подобный шифр

Оригинальная `tea(block,key)` обрабатывает два 32-битных little-endian слова на протяжении **32 раундов**, используя константу `0x9e3779b9`. Номера 32-битных частей 128-битного ключа определяются текущей суммой:

```python
v0=u32(v0+(((u32(v1<<4)^(v1>>5))+v1)^(su+k[su&3])))
su=u32(su+0x9e3779b9)
v1=u32(v1+(((u32(v0<<4)^(v0>>5))+v0)^(su+k[(su>>11)&3])))
```

Синтаксис этого исходника важен: это TEA-семейство с изменённым выбором ключевых слов, а не стандартный AES или простая XOR-маска.

## 7. Проверка MAC

MAC имеет 128-битное состояние из четырёх little-endian слов. Каждый 4-байтовый блок входа XOR-ится с первым словом; две восьмибайтные половины прогоняются через `tea()` с `k0` и `k1`, затем перемешиваются:

```python
vals[3]^=vals[1]
vals[0]^=vals[2]
```

Проверка отпечатка начинается с фиксированного IV:

```python
IV=struct.pack('<4I',0x67452301,0xefcdab89,0x98badcfe,0x10325476)
calc=mac(IV,all_data,keys[2],keys[3])
# calc должен совпасть с license[8:24]
```

В историческом запуске совпадение было подтверждено. Сам оригинальный `solve.py` печатает оба MAC, но не вызывает `assert` — при самостоятельном прогоне их обязательно нужно сравнить.

## 8. Получение ключа и флага

Второй MAC-контур стартует с нулевого состояния и обрабатывает **три группы** с `keys[0]` и `keys[1]`:

```python
state=bytes(16)
for data in (cpuid, vol+reg, uuid+macaddr):
    state=mac(state,data,keys[0],keys[1])
```

После `transform(state)` — побитовые циклические сдвиги, XOR и сложение над 32-битными словами — получается **16-байтовый ключ гаммы**.

Из `license[24:32]` берётся 8-байтовый nonce, из `license[32:96]` — 64 байта шифртекста. На блоке `j`:

```python
stream=tea(struct.pack('<2I',u32(v0+j),v1),derived_key)
plain_block=cipher_block XOR stream
```

Склеиваем восемь блоков. В старом решении на выходе получен правильный `gctf{...}`, принятый платформой.

## 9. Как воспроизводить

```sh
tar -xzf mircosoft.tar.gz
python3 scripts/extract_minidump.py mircosoft/admin_machine.dmp --out-dir /mnt/data/mircosoft_work
```

Для оригинального финального скрипта необходимы `/mnt/data/mircosoft_work/mircosoft/license.bin` и `/mnt/data/mircosoft_work/unpacked_pe.bin` (полученный распаковкой внутреннего PE). Запуск:

```sh
python3 scripts/solve.py
```

Путь `/mnt/data/mircosoft_work` захардкожен **в историческом оригинальном скрипте**; для другой машины его следует заменить. В текущем архиве нет ранее сохранённого распакованного PE: поэтому здесь **не заявляется новый полный прогон финального дешифратора**.
