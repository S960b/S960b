# Hermes MCP · Stage 35V

35U получил 7 запросов к MCP с правильным ключом, в том числе 3 ответа 403 с признаками `POST / other / deny_rpc_method`. Выражение в `35u_observer.py:74–84` выдаёт эту пару только для разобранного JSON-объекта с полем method типа string, за пределами обоих списков. Все методы, которые 35G разрешает как обычные RPC, распознаются в 35U. На совпадающем коде `guard35g.py:59,108–110` такой запрос до внутреннего сервера не доходит. Точное имя 35U заменил на other до записи. Для двух более ранних ответов 35T ветка индивидуально не установлена. Записи unsupported_channel суммируются отдельным поиском по журналу туннеля с момента активации. Они не связаны идентификатором с тремя запросами.

## Установка и сбор

Файл ZIP сам исполняется Python. Все команды для пользовательского сеанса kali. Для первой команды положить скачанный файл в Downloads и проверить SHA-256 из сообщения. Следующие команды используют установленную частную копию.

```bash
python3 -IB "$HOME/Downloads/hermes-pg-stage35v.zip" capture
```

Дождаться `STAGE35V_CAPTURE_ACTIVE_20MIN_REAL_SDK_11_TOOLS_READONLY`, затем один раз выполнить «Создать плагин» в нужной рабочей области. Пока идёт проверка, другие клиенты, имеющие этот же доверенный ключ, тоже могут обращаться к серверу. Для атрибуции окну регистрации исключить параллельные ручные пробы. Когда ChatGPT ответит, выполнить:

```bash
python3 -IB "$HOME/hermes-pg-stage35v/stage35v.zip" collect
```

`collect` восстанавливает исходную службу 35G и выводит счётчики реальных срабатываний `unknown_method_denied`. Если таймер уже сработал, сохранённые события доступны. При наличии подтверждённой постоянной установки collect только печатает отчёт. Повторное чтение всегда доступно через `report`.

Поле `name` извлекается в обработчике исключения реального 35G. Обычные имена, включая неизвестные расширения, пишутся в `~/hermes-pg-stage35v/denials.tsv` с правами 0600 внутри каталога 0700. Сохраняется только один идентификатор метода из тела. На ошибочном ключе код до этой точки не доходит. Параметры, tool name, тело запроса, ключ и session ID туда не записываются. Общий отчёт раскрывает известные названия протокола. Если получен `LOCAL_NAME_XX`, посмотреть точный маркер на самой Kali:

```bash
python3 -IB "$HOME/hermes-pg-stage35v/stage35v.zip" names
```

Незнакомое имя можно передать после просмотра, если это обычное название RPC. Для строки с пробелами, управляющими символами, подозрительно длинным сегментом либо недопустимыми символами сохраняется `[redacted]`; восстановить её из пакета нельзя. При заполнении 64 КиБ стоит маркер неполной записи. Оба случая блокируют автоматическое расширение. Если найден новый частный идентификатор, его смысл и реализация требуют проверки до изменения доступа.

## Условная правка и приёмка

`trial` формирует добавление к `guard35g.METHODS` ровно из уникальных ранее отклонённых имён. Для автоматической проверки в этой версии разобраны два конкретных read-only RPC: `server/discover` и `skills/list`. Оба являются документированными методами. Ни одно из этих названий не установлено по историческим 35U-маркерам. Любое другое имя или пустой набор завершит trial до изменения службы. Для такого имени нужен отдельный разбор его назначения, поддержки в SDK и границы доступа. Пакет не возвращает искусственный ответ на неподдерживаемую операцию.

Если `collect` показал только методы из этих двух, запустить:

```bash
python3 -IB "$HOME/hermes-pg-stage35v/stage35v.zip" trial
```

Временно изменяется только внешний список методов. Транспорт, проверку Host/Origin, версий, сессий, FastMCP и список инструментов обслуживает исходный код. Пакет проверит отклонение неверного и отсутствующего ключа, старый initialize/notifications/initialized/tools/list, реальный read-only вызов managed_health, чтение пилота через managed_list. Для server/discover дополнительно требуются валидный результат с версией 2026-07-28, capability tools и успешное перечисление 11 инструментов в этой версии. Для skills/list нужны объявленная capability расширения и ожидаемый пустой список в реальном ответе. Если SDK не поддерживает наблюдаемый RPC, trial завершается с откатом. Точную причину такого результата нужно проверять отдельно; один новый элемент METHODS не реализует операцию в SDK.

При `STAGE35V_TRIAL_ACTIVE_20MIN_REAL_SDK_11_TOOLS_READONLY` проверить в ChatGPT создание плагина, наличие 11 инструментов managed_* и результат managed_health с `ok=true`, `connected=true`, `role=bridge_chatgpt` и `write_permit_present=false`. Только после фактического успеха в интерфейсе закрепить конфигурацию в течение пробного окна:

```bash
python3 -IB "$HOME/hermes-pg-stage35v/stage35v.zip" commit
```

Если срок окна кончился до commit, исходная служба автоматически восстановится. Сохранённые имена можно использовать для повторного trial. При появлении дополнительного непросмотренного метода commit блокируется. После подтверждения временный и постоянный ExecStart идентичны, дополнительный перезапуск для commit не нужен. При любом отрицательном результате вернуть отчёт с кодом завершения. Ручной откат доступен и после commit:

```bash
python3 -IB "$HOME/hermes-pg-stage35v/stage35v.zip" rollback
```

## Влияние на систему и проверки

Единственная перезапускаемая служба — `hermes-pg-stage35c-static-shadow.service`. Перезапуск прерывает её текущие MCP-сессии. Порт остаётся 18777. Для capture и trial используется временный systemd drop-in в /run/user; автотаймер вооружается до его создания. Идентификатор таймера привязан к конкретному запуску, просроченный таймер не откатит другой запуск. Для установки проверяются исходный ExecStart/PID, факт завершения 35U, текущий адрес процесса туннеля и отсутствие разрешения записи. Затем исходный 35G runner проверяет SHA-256 зависимостей. Конфигурация туннеля, учётные данные, роли, БД, прежние наблюдатели и плагины не модифицируются.

Пакет содержит код, тесты и точную копию guard35g.py из аудита как тестовую фикстуру. В рабочей службе используется установленный оригинал 35G после проверки хешей. В среде разработки выполнены тесты Python, включая HTTP/SSE на реальном локальном TCP-порту с mcp 1.29.0 и фиктивным read-only инструментом. Тесты управляющих операций используют имитацию systemd. На целевой машине установленный SDK проверяется штатным read-only probe при запуске. Для воспроизведения тестов на копии распаковать ZIP во временный каталог, из него запустить `python3 -B -m unittest discover -s tests -p 'test*.py' -v` с Python, Starlette, uvicorn и mcp 1.29.0.
