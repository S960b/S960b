## Правила Git-диалогов

1. **Один task_id = одна ветка `dialogs/<task_id>`.** Не объединять эти ветки в `main`, не переиспользовать идентификаторы и не очищать их массово.
2. **Проверить фактический MCP-интерфейс.** Если доступен авторизованный `dialog_append`, использовать его. В наблюдаемом API (06.11.2026) были только `dialog_index` (метаданные) и `dialog_notice` (подтверждение уже записанного Git-коммита). Для этого ограниченного ручного пути обязательны preflight полного snapshot **до любого Git POST**, точный формат времени `YYYY-MM-DDTHH:MM:SSZ`, единственный parent, CAS без force и сверка кандидата до ref. Порядок подробно дан в [CHATGPT_GIT_BRIDGE.md](CHATGPT_GIT_BRIDGE.md); он не заменяет гарантий AppendStore.
3. Запись в Git, доставка в MT-сессию и ответ MT — три разные стадии. `waiting_for=mt` не означает «MT выполняет». Не повторять неоднозначные публикации.
4. Кнопка **«Удалить задачу»** удаляет Git-ref соответствующего диалога. Прежде чем удалять, убедиться, что его история больше не нужна.
5. В обычном чате ChatGPT не гарантирует автономное продолжение задачи при появлении ответа MT; новый ответ может потребовать обращения «прочитай ответ».

## Работа с исходниками и проверками

Контролируемое тестирование проводить на точном Git SHA в отдельной копии, не на рабочей директории, используемой службами. Пример из корня изолированной копии:

```sh
PYTHONPATH=src python -m pytest tests/ -q
PYTHONPATH=src python -m compileall -q src tests
node --check review/mt-inbound-plugin/mt-git-inbox.mjs
node --test review/mt-inbound-plugin/tests_*.mjs
```

Потребуются зависимости проекта и подходящее тестовое Python/Node окружение. Тестовые команды не являются установочным скриптом. Для `mcp` SDK локальный запуск может потребовать корректного `PYTHONPATH` к site-packages. Последние зафиксированные приёмки: 1143 Python-теста на P33-интеграции и 19 Taskboard-тестов P35; после новых изменений проверки нужно выполнить заново.

**Production без специальных поручений не трогать:** сервисы `hermes-bridge` и `git-dialog-taskboard`, системные unit/drop-in, credentials, MT `state.json`, SQLite и пользовательские MT-сессии. Секреты, токены, локальные БД, данные чужих задач и снимки диалогов не публиковать в `main`.
