# Куча дежавю (pwn)

Сервис принимает на вход программу для собственного интерпретатора и исполняет её. На
сервере рядом с интерпретатором лежит файл с флагом, а доступ к файлам идёт через
отдельный брокер по общей области памяти: клиент отображает сегмент, пишет туда запрос и
читает ответ.

В задаче один исполняемый файл `dejaheap_v10`: статический, stripped, non-PIE, Linux
x86-64. Он реализует виртуальную машину со своим текстовым языком, сборщиком мусора и
инструкциями для работы с брокером.

Цель: заставить сервис отдать содержимое файла с флагом.

Опорные факты:

- Куча из двух полупространств по 64 КиБ, сборщик копирующий, аллокатор bump.
- Вектор экспорта по адресу `0x50cea8` не входит в корни сборщика, поэтому
  зарегистрированный объект остаётся висячим после сборки.
- Копирование в общую область выполняется на `ret` кадра-владельца записи.
- Подпись запроса считается по ключу, который приходит в ответе на `HELLO` и случаен на
  каждое соединение.

Файлы:

- `assets/dejaheap_v10` - интерпретатор в исходном виде
- `scripts/dh_runtime_mac_vm.py` - генератор программы с подписью, вычисляемой на лету
- `scripts/dh_op1_probe_gen.py` - генератор программы с поддельным запросом на открытие
- `scripts/dh_mac_exact.py` - точная реализация подписи для сверки с нативным кодом
- `scripts/win_open0_full.vm` - готовый байткод победного запуска
- `scripts/submit_remote.py` - отправка программы на сервис

Полный путь решения описан в `solve.ru.md`.
