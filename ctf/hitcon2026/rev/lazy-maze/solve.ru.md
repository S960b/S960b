# Lazy-Maze: ход решения

## 0. Общий план

Сервер - `nc <host> 9999`, внутри лабиринт на Python 3.15. Лабиринт «двигается»: двери и
комнаты меняются по мере прохождения, а часть комнат выполняет эффекты. Финальная комната
запускает `exec(state.script)`, где `state.script` - строка, которую ты собирал каждым
шагом. План был:

1. Прочитать выданный Python-проект и понять модель комнат/эффектов.
2. Понять, что ленивые импорты Python 3.15 - это механизм таймингов: сервер вызывает
   `sys.set_lazy_imports("all")` и фильтр, поэтому код модуля комнаты исполняется только
   тогда, когда что-то форсирует жадный импорт этого модуля.
3. Смоделировать лабиринт как граф, рёбра которого меняются в зависимости от того, какие
   модули уже импортированы (и какие эффекты собрали символы).
4. Найти маршрут, который доходит до выхода с компилируемым `state.script`: строковый
   литерал и `+breakpoint()`.
5. На сервере `breakpoint()` открывает PDB раньше, чем ошибка типа сложения, а PDB - это
   удалённый python-шелл: читаем из него файл флага.

## 1. Выданный проект

Зачем этот шаг: в архиве лежат настоящие исходники, так что «реверс» - это чтение Python,
а не дизассемблирование.

`lazy-maze-d040a24eb3619536.tar.gz` содержит полный Python-проект (`release/`):
- `game.py` - драйвер; вызывает `sys.set_lazy_imports("all")`,
  `sys.set_lazy_imports_filter(...)`, хранит позицию и динамически резолвит модуль текущей
  комнаты;
- `maze_state.py` - единое глобальное состояние: `position`, `script`, `controls`,
  `exits`, `room_modules`, `done`;
- `m/__init__.py` - динамические импорты модулей комнат;
- `m/x_*.py` - тысячи модулей комнат: стены, комнаты-переключатели импортов, комнаты
  эффектов и одна целевая комната;
- `m/x_d03594116a69.py` - выход, выполняет `exec(state.script)`;
- `runner.py` / `server.py` - TCP-обёртка.

В локальных файлах флага нет; строка флага - `hitcon{br4nd_n3..._c0ntrol}`.

## 2. Механизм: ленивые импорты как переключатель

Зачем этот шаг: весь трюк в том, что комната «случается», только когда её модуль
импортирован, а управляет этим фильтр ленивых импортов Python 3.15.

`game.py` ставит `sys.set_lazy_imports("all")` плюс фильтр. Модуль вроде `m.x_abc` при
навигации только *планируется*; его настоящий код (стены, эффекты, доп. символы скрипта)
выполняется, когда импорт форсируется. Какие импорты форсируются, решает фильтр из
`sys.get_lazy_imports_filter()` - и несколько управляющих комнат *меняют фильтр* (то, какие
неймспейсы грузятся жадно). Значит, одна и та же позиция на доске ведёт себя по-разному в
зависимости от истории импортов. Лабиринт превращается в систему, чьё состояние -
(позиция, конфигурация фильтра, `state.script`, раскладка стен), а не просто координата.

## 3. Эффекты: строитель полезной нагрузки

Зачем этот шаг: набор комнат, добавляющих символы, мал и имеет ограничения (комнаты
кавычек и обратного слэша особые), так что полезную нагрузку приходится выписывать ровно
теми символами, которые доступны.

Комнаты-эффекты дописывают в `state.script`:

```python
state.script += chr(...)
```

Целевая комната исполняет `exec(state.script)`. Нагрузка, являющаяся валидным строковым
литералом, работает; всё, что синтаксически невалидно, убивает exec до передачи
управления. Собранная строка обязана быть полным литералом, за которым идёт выражение.
Победная нагрузка:

```python
"JQ\",~"+breakpoint()
```

- `"JQ\",~"` - валидный строковый литерал (`\"` - экранированная кавычка);
- `+breakpoint()` - обычное выражение;
- `breakpoint()` входит в PDB раньше, чем возникнет TypeError сложения строки с None.

Внутри PDB выполняем `import os; ...` для списка файлов и чтения флага; `solve.py` шлёт
эти команды автоматически и ищет флаг в выводе.

## 4. Поиск маршрута

Зачем этот шаг: полезная нагрузка - это ограничение; поиск прогулки, которая её
компилирует, - комбинаторный поиск по графу с состоянием.

Поиск держит (позиция, множество «импортировано», состояние фильтра, стены) и
перебирает ходы в четырёх направлениях, применяя семантику ленивых импортов так, что
посещение комнаты впервые сначала триггерит её модуль (и её эффект). Победный маршрут -
1356 ходов, от (19,19) до (37,1), и собирает ровно `"JQ\",~"+breakpoint()` (см.
`scripts/expected_code.txt`). Маршрут сжат в `scripts/route.json`; каждая запись несёт
направление и ожидаемую координату, чтобы клиент мог проверить каждый шаг.

`solve.py` льёт все ходы на сервер одним потоком и ждёт промпта `(Pdb)`; валидация
маршрута в клиенте отклоняет любой шаг, у которого вычисленная позиция отличается от
записанной.

## 5. Проверка

Зачем этот шаг: собственный райтрайт архива надо проверить, а не верить ему; локальный
верификатор гоняет настоящие модули комнат.

`verify_local.py` распаковывает оригинальный релиз во временный каталог, ставит маленький
`_lazy_shim`, эмулирующий `set_lazy_imports_filter` / `get_lazy_imports_filter` Python
3.15 на Python 3.13, и проигрывает все 1356 ходов против оригинальных модулей. Ожидаемый
вывод:

```text
Steps: 1356 PDB: True Blocked: 0
Script: '"JQ\\",~"+breakpoint()'
Expected: '"JQ\\",~"+breakpoint()'
VERIFIED_LOCAL_PDB
```

Это доказывает, что маршрут геометрически валиден и даёт ровно нужную нагрузку и живой
промпт `(Pdb)`. Это не доказывает приём флага remote; в локальном тесте никакого секрета
нет.

Также я запускал `python3 solve.py --host <host> --port 9999` против remote: клиент
подключался, слал маршрут, доходил до PDB и читал флаг. Значение флага хранится отдельно
и в этом репозитории замаскировано.

## 6. Тупики (не повторять)

- **Считать лабиринт статичной сеткой.** Стены меняются при импорте, поэтому наивный BFS
  находит пути, которые позже становятся заблокированными или дают не тот скрипт.
- **Выписывать нагрузку обычными символами.** Доступные комнаты-эффекты не могут
  построить простую строку `"breakpoint()"`; `JQ",~` - ровно те символы, что доступны, и
  экранированная кавычка обязательна для литерала.
- **Игнорировать фильтр ленивых импортов.** Без эмуляции того, какие модули грузятся
  жадно, раскладка стен и тайминги эффектов неверны, и маршруты «случайно» падают на
  сервере.
- **Отвечать на приветствие сервера.** Сервер ждёт только команды движения; лишний текст
  ломает прогон.

## Короткая версия

Лабиринт - программа на Python 3.15, чьи комнаты грузятся ленивыми импортами; какой модуль
реально выполнится (и поменяет стены или допишет символ в `state.script`), зависит от
состояния фильтра импортов, которое меняют управляющие комнаты. Выход исполняет собранный
скрипт, поэтому цель - маршрут на 1356 ходов, собирающий литерал `"JQ\",~"` плюс
`+breakpoint()`; на сервере `breakpoint()` открывает PDB, и флаг читается из процесса
командами PDB.

## Выводы

- Новые возможности языка - законная тема для сервера задачи: `sys.set_lazy_imports`
  сделало «состояние» лабиринта включающим то, какой код реально выполнялся.
- Когда цель исполняет контролируемую тобой строку, выгоднее целиться в отладчик
  (`breakpoint()`), а не в чистый RCE - PDB уже сам по себе REPL.
- Локальный верификатор, проигрывающий оригинальные модули, лучше доверия ручной нагрузке;
  держи маршрут проверяемым (направление + координата), чтобы сломанный маршрут ловился в
  клиенте до обращения к серверу.
